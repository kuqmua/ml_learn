## 1. Словарь и задача предсказания

В `data/names.txt` 32 033 имени. Буквы a–z получают индексы 1–26, точка — 0. Точка означает и пустой начальный контекст, и конец имени. Для `emma` получаются:

| Контекст X | Цель Y |
|---|---|
| `...` | `e` |
| `..e` | `m` |
| `.em` | `m` |
| `emm` | `a` |
| `mma` | `.` |

Каждая строка X — три целых индекса, Y — один индекс. Всего 228 146 примеров. Контекст сбрасывается между именами: последнее имя не подсказывает начало следующего. Сначала объединяем одинаковые имена в группы, перемешиваем **группы** с seed 42 и выделяем 80% уникальных имён в train, 10% в dev и 10% в test. Все копии одного имени остаются в одном наборе; частоты и все 32 033 записи сохраняются. Наборы не пересекаются по именам; число записей зависит от перемешивания групп. Затем строим словарь только по train и создаём контексты отдельно для каждого набора. Неизвестная в train буква в dev/test приводит к ошибке, а не расширяет словарь. Совпадения коротких контекстов у разных имён допустимы.

## 2. Lookup вместо one-hot

Таблица эмбеддингов `C` имеет форму `(27,10)`. Строка `C[i]` — обучаемые координаты символа i. Умножение one-hot вектора длины 27 на C даёт ту же строку, но прямой lookup не тратит вычисления на нули. `C[X]` для мини-батча даёт `(B,3,10)`. Координаты трёх символов объединяются в `(B,30)` с сохранением их порядка.

В программе создаётся одна модель: она обучается и генерирует имена. Отдельная маленькая модель из вводных ячеек notebook не запускается.

## 3. Полная модель

| Тензор | Форма | Параметров |
|---|---|---:|
| C | 27 × 10 | 270 |
| W1 | 30 × 200 | 6000 |
| b1 | 200 | 200 |
| W2 | 200 × 27 | 5400 |
| b2 | 27 | 27 |
| Всего | | **11 897** |

Прямой проход: `emb = C[X]`, `x = flatten(emb)`, `h = tanh(x W1 + b1)`, `logits = h W2 + b2`. Для B=32 формы: `(32,3,10) → (32,30) → (32,200) → (32,27)`. Смещения прибавляются к каждой строке. `tanh` нужен для нелинейности; два линейных слоя без него можно свернуть в один.

По умолчанию все пять тензоров инициализируются стандартными нормальными числами, как по смыслу в notebook. В программе один генератор с seed 42: после перемешивания групп имён он продолжает ту же последовательность для инициализации, выбора батчей и генерации имён. Большие начальные logits дают большую начальную ошибку; здесь намеренно сохранена исходная инициализация, без добавления BatchNorm или Adam.

Для эмбеддингов C сохранена альтернатива `initialize_embeddings_regular_cube`: при 27 символах она создаёт все узлы решётки 3 × 3 × 3 с координатами `-sqrt(3), 0, sqrt(3)` в первых трёх осях. Остальные семь координат сначала нулевые, затем обучаются. Для включения установи `USE_REGULAR_CUBE_EMBEDDINGS = true`; по умолчанию остаётся нормальная инициализация. Нормальная C создаётся в обоих режимах, поэтому выбор куба не меняет случайные числа остальных начальных весов.

Cross-entropy для одного примера:

```text
m = max(logits)
loss = m - logits[target] + ln(sum(exp(logits - m)))
```

Это та же `-ln(probability_of_correct_character)`, но без переполнения `exp` и без `ln(0)`. Loss усредняется по примерам; случайное равномерное предсказание даёт `ln(27) ≈ 3.296`.

## 4. Обратный проход и SGD

Исходная CPU-реализация находится внутри функции `main` в `src/main.rs`, включая определения типов, реализации трейтов и численные вычисления. Открой блок расчёта градиентов внутри цикла обучения. Вместо `loss.backward()` здесь явно записано правило цепочки:

```text
dlogits = (softmax(logits) - one_hot(Y)) / B
dW2 = hᵀ dlogits                  db2 = sum_rows(dlogits)
dh = dlogits W2ᵀ
da = dh * (1 - h²)
dW1 = xᵀ da                       db1 = sum_rows(da)
dx = da W1ᵀ
dC[буква] += соответствующие координаты dx
```

Последний `+=` принципиален: одна буква может встретиться несколько раз внутри контекста и в разных примерах мини-батча. Все вклады должны сложиться. На каждом шаге выделяются нулевые градиенты. Все производные используют старые W1/W2, после чего локальный блок обновляет все параметры: `p -= lr * grad`.

Обучающие примеры берутся последовательно батчами по 32 без перемешивания между эпохами. Последний батч может быть короче: каждый пример используется ровно один раз за эпоху. После конца набора следующий проход начинается с начала в том же порядке. Выполняются 200 000 шагов: `lr=0.1` на шагах 0…99 999 и `lr=0.01` на остальных. Переменная `training_steps` сокращает или продлевает число шагов, но не переносит границу смены lr. Это число обновлений, а не эпох.

## 5. Качество и генерация

После обучения считаем среднюю cross-entropy по **всему** train и dev без изменения параметров. По dev можно выбирать размер модели и скорость обучения. Test используется только для итоговой оценки: в notebook он подготовлен, но не оценён; здесь метрика дополнительно выводится. Не подбирай настройки по test.

Loss отдельных мини-батчей колеблется, поскольку на каждом шаге выбираются другие примеры. Итоговые train/dev/test loss считаются по полным наборам и печатаются в консоль.

Генерация начинает с `...`. Сеть выдаёт распределение вероятностей следующего символа, из него случайно выбирается индекс, контекст сдвигается, и процесс повторяется до точки. Это sampling, а не argmax: можно получить разные имена. Sampling использует общий генератор, продолжая последовательность после обучения. Изменение числа весов или шагов обучения меняет последующие случайные выборы. Ограничение 100 символов защищает от бесконечного вывода плохо обученной модели; усечённый результат явно помечается.

| `first_layer_weights`, `first_layer_biases` | W1 и b1: веса и смещения первого слоя |
| `first_layer_activations` | Выходы нейронов первого слоя после tanh |

| `learning_rate` | Скорость обучения: множитель при вычитании градиента |
| `next_character_score_gradients_as_f32_from_minus1_to1` | Производные ошибки по выходным оценкам букв |
| `first_layer_pre_activation_gradients` | Производные ошибки по суммам первого слоя до tanh |
| `first_layer_weight_gradients` | Производные ошибки по весам W1 |
| `input_coordinate_gradient` | Производная ошибки по одной координате входного вектора |

Суффикс `_index` обозначает позицию, `_count` — количество, `_gradients` — производные ошибки по соответствующим значениям. `Model` хранит C, W1, b1, W2 и b2 в отдельных именованных полях, а соответствующие производные — в поле `gradients: ModelGradients`; шаг SGD явно связывает каждое поле модели с его градиентами. Длина контекста задаётся `CONTEXT_LENGTH = 3` и используется в типе контекста, размерах W1, подготовке примеров и генерации. Размеры эмбеддинга и первого слоя заданы константами `EMBEDDING_DIMENSIONS = 10` и `FIRST_LAYER_SIZE = 200`. W1 хранится как `[[FiniteF32; FIRST_LAYER_SIZE]; CONTEXT_LENGTH * EMBEDDING_DIMENSIONS]`, b1 — как `[FiniteF32; FIRST_LAYER_SIZE]`. C имеет тип `NonEmptyVec<[FiniteF32; EMBEDDING_DIMENSIONS]>`, W2 — `NonEmptyVec<[FiniteF32; FIRST_LAYER_SIZE]>` (один массив весов на выходной символ), b2 — `NonEmptyVec<FiniteF32>`. Градиенты повторяют формы параметров: `ModelGradients` хранит `FiniteF32` сразу при накоплении. `accumulate_gradient_product` накапливает `input_or_weight × output_gradient`, а `accumulate_bias_gradient` прибавляет `output_gradient` без множителя 1. Каждое произведение и новая сумма проверяются на конечность; ошибка указывает место переполнения. Число строк C, W2 и b2 задаётся размером словаря при инициализации; преобразования сохраняют эти длины. Число скалярных параметров учитывает обе размерности матриц. Вход первого слоя, его активации и градиенты — массивы фиксированной длины; мини-батч заимствуется как `NonEmptySlice` с максимум `BATCH_SIZE = 32` примерами.

## Прямой проход, обратный проход и шаг обучения

`Model` хранит параметры и накопители градиентов в одном объекте. `zero_grad(&mut self)` обнуляет все пять групп градиентов перед батчем, сохраняя выделенную память. `forward(&self, context)` вычисляет предсказание и сохраняет промежуточные значения в `ForwardPassResult`. `backward(&mut self, forward_result, score_gradients)` накапливает производные в `self.gradients`, не изменяя параметры. `step(&mut self, learning_rate)` обновляет параметры по накопленным градиентам после обработки всего батча.

Порядок вызовов: `model.zero_grad()?` → для каждого примера `model.forward(...)`, `SoftmaxCrossEntropy::forward(...)`, `SoftmaxCrossEntropy::backward(...)`, `model.backward(...)` → один `model.step(learning_rate)?`. `backward` добавляет вклад каждого примера; обнуление внутри этого цикла уничтожило бы вклады предыдущих примеров. `step` оставляет градиенты доступными для просмотра, а следующий `zero_grad` очищает их.

| Операция | `forward` | `backward` |
|---|---|---|
| `Model` | Контекст → эмбеддинги → первый слой → `tanh` → оценки символов | Градиенты оценок → второй слой → `tanh` → первый слой → эмбеддинги |
| `SoftmaxCrossEntropy` | Оценки и правильный символ → вероятности и ошибка | Вероятности и правильный символ → `(p − target) / batch_len` |
| `Tanh` | `output = tanh(input)` | `input_gradient = output_gradient × (1 − output²)` |

`backward` не восстанавливает вход из выхода. Он передаёт производную ошибки назад по правилу цепочки. Градиентный спуск — следующий, отдельный этап `Model::step`: `parameter -= learning_rate * gradient`.

В цикле обучения сначала вызываются `model.forward(...)` и `SoftmaxCrossEntropy::forward(...)`. Далее комментарии ограничивают backpropagation: `SoftmaxCrossEntropy::backward(...)` и `model.backward(...)`. Внутри `Model::backward` пять групп градиентов по-прежнему изменяются в отдельных блоках. Между градиентами второго и первого слоёв вызывается `Tanh::backward(...)`. После завершения батча выполняется один `model.step(...)`.

`ForwardPassResult` хранит исходные индексы контекста, объединённые эмбеддинги, активации первого слоя и оценки символов. Для `backward` используется результат того же прямого прохода; между этими вызовами параметры не меняются. `ModelGradients::zeros(vocabulary_len)` создаёт нулевые накопители при инициализации модели. Перед каждым батчем `Model::zero_grad` обнуляет их на месте. При генерации имён используется только `forward`; градиенты остаются в модели, но не участвуют в предсказании. Размер батча передаётся в `SoftmaxCrossEntropy::backward` как `NonZeroUsize`, поэтому деление на ноль исключено; усреднение выполняется ровно один раз.

## Проверка входных данных через типы

Вместо входных `assert!` используются типы с проверяемым созданием через `TryFrom` или методы словаря:

- `NonZeroUsize::new(число)` вместе с `ok_or(...)?` проверяет положительное число шагов.
- `Vocabulary` хранит уникальные буквы в алфавитном порядке и точку под индексом 0. `new` строит словарь из текста, `len` возвращает его размер, `dot_index` возвращает индекс точки для границ имени и начального контекста, `index_of` находит индекс символа, `character` возвращает символ с проверкой границ. `[VocabularyCharacterIndexAsUsize; CONTEXT_LENGTH]` хранит индексы символов контекста; целевой символ имеет тот же тип. Числовой индекс создаётся через `VocabularyCharacterIndexAsUsize::try_from((число, &vocabulary))`: допустимы значения от 0 до `vocabulary.len() - 1`. Поле `.0` содержит число для обращения к тензорам. Все типы находятся в одном модуле, поэтому приватность поля не запрещает прямой конструктор внутри `main.rs`; рабочий код создаёт числовые индексы через `TryFrom`. Проверка относится к словарю при создании; сам индекс не хранит его идентичность.
- `Name::try_from(строка)` принимает одно непустое имя из a–z. Исходный список, группы и выборки содержат проверенные `Name`, а непустота коллекций выражена `NonEmptyVec`.
- `NonEmptySlice::try_from(срез)` проверяет непустой срез без копирования: его используют обучающие примеры и входные оценки `SoftmaxCrossEntropy::forward`.
- `NonEmptyVec<CharacterProbabilityAsF32From0To1>` — непустой вектор вероятностей в результате `SoftmaxCrossEntropy::forward`. Проверка `TryFrom` отклоняет пустой вектор, доступ через срез не позволяет удалить элементы; `IntoIterator` генерируется через `derive_more`. Метод `map` сохраняет число элементов и непустоту при преобразовании, например вероятностей в градиенты. `Deref<Target = [T]>` генерируется через `#[derive(derive_more::Deref)]` с `#[deref(forward)]`.

Ошибки возвращаются строками `&'static str` и передаются вызывающему коду через `?`. Непустота закреплена также в наборах имён после разделения, примерах, параметрах и градиентах модели и выходных оценках. Обычный `Vec` остаётся для временных накопителей, которые действительно бывают пустыми при построении. Проверка `Name` запрещает пустое имя и символы вне a–z. `NonEmptyVec` не реализует `DerefMut`: изменение численных элементов выполняется через `.0` без изменения длины. Как и у индексов, локальные определения внутри `main` не защищают от прямого обхода конструктора самим кодом урока.

`CrossEntropyLossAsNonNegativeF32` проверяет конечность и неотрицательность как отдельного, так и среднего loss. Вероятности проверяются на диапазон `[0, 1]`. `FiniteF32` хранит конечное число: этот тип используют параметры `Model`, поля `ForwardPassResult` и градиенты при накоплении. Проверки выполняются при инициализации, завершении вычислений и обновлении параметров; промежуточная арифметика остаётся на `f32`. Скорость обучения имеет тип `LearningRateAsPositiveFiniteF32`, запрещающий также ноль и отрицательные значения. Веса, координаты и градиенты могут быть отрицательными, поэтому ограничение вероятностей к ним неприменимо. `From<&NonEmptyVec<T>>` для `NonEmptySlice<T>` заимствует уже проверенные данные без повторной проверки непустоты. `derive_where` генерирует `Copy` и `Clone` для `NonEmptySlice` без лишних ограничений на элементы.

## Локальная область видимости

Единственное определение верхнего уровня в `src/main.rs` — функция `main`. Все структуры и реализации находятся внутри неё; объявлений `mod`, `use` и дополнительных Rust-файлов нет. `Name` и его реализации локальны блоку подготовки данных. `Model`, `ModelGradients`, `ForwardPassResult`, `SoftmaxCrossEntropy`, `Tanh` и типы градиентов доступны внутри `main`, чтобы методы могли передавать явно типизированные результаты друг другу.

Модель создаётся локальным блоком с инициализацией параметров из нормального распределения. Замыкание `build_previous_vocabulary_character_indexes_and_next_character_indexes` локально блоку подготовки данных и захватывает словарь. Замыкание `loss` использует `Model::forward` и `SoftmaxCrossEntropy::forward` для оценки выборки. Генерация имён использует те же прямые операции без `backward` и `step`. Размеры выходных массивов методов определяются полями модели; `Model` не хранит копию размера словаря или ссылку на него. Вспомогательные функции накопления локальны `Model::backward`, замыкание обновления среза — `Model::step`.

Полные пути стандартной библиотеки, `rand` и `rand_distr` указаны непосредственно в местах обращения, без `use`. Число шагов хранится в `std::num::NonZeroUsize`.

Сборка проверяется через `cargo check`; обучение запускается через `cargo run`.

Локальные значения и кортежи имеют явные подписи типов. У замыканий явно указаны типы параметров и результата; их анонимный тип выводится Rust. В `for` Rust не допускает аннотацию типа у шаблона, поэтому тип элемента указан через `let` в начале тела цикла.

`NextCharacterScoreGradientAsF32FromMinus1To1` и `TargetScoreGradientAsF32FromMinus1To0` объявлены внутри `main` и связывают `SoftmaxCrossEntropy::backward` с `Model::backward`. `NextCharacterScoreGradientAsF32FromMinus1To1` различает производные по оценкам следующего символа: `Target` содержит проверенный `TargetScoreGradientAsF32FromMinus1To0` в диапазоне [−1, 0], а `Other` использует проверенный диапазон [0, 1]. Значения уже поделены на фактический размер батча. При построении коллекции `Target` ставится только на позицию правильного символа; сам enum количество таких вариантов не ограничивает.

## Простой вариант

В `src/simple.rs` тот же MLP записан обычными `f32`, массивами и векторами: без проверяющих обёрток и дополнительных вариантов инициализации. Комментарии ведут от подготовки имён до генерации. Весь алгоритм находится в одной `main`, без собственных структур и методов. Повторяющиеся вычисления оформлены локальными closure. Градиенты хранятся в отдельных массивах той же формы, что параметры. Вывод в консоль отсутствует. Это самостоятельная версия, основной `src/main.rs` не используется.

Из папки урока:

```bash
cargo run --bin simple
```

Число шагов задаётся константой `TRAINING_STEPS` в `src/simple.rs` (200 000). Обычный `cargo run` по-прежнему запускает основную версию.

## 1. Словарь и задача предсказания

В `data/names.txt` 32 033 имени. Буквы a–z получают индексы 1–26, точка — 0. Точка означает и пустой начальный контекст, и конец имени. Для `emma` получаются:

| Контекст X | Цель Y |
|---|---|
| `...` | `e` |
| `..e` | `m` |
| `.em` | `m` |
| `emm` | `a` |
| `mma` | `.` |

Каждая строка X — три целых индекса, Y — один индекс. Всего 228 146 примеров. Контекст сбрасывается между именами: последнее имя не подсказывает начало следующего. Сначала объединяем одинаковые имена в группы, перемешиваем **группы** с seed 42 и выделяем 80% уникальных имён в train, 10% в dev и 10% в test. Все копии одного имени остаются в одном наборе; частоты и все 32 033 записи сохраняются. Наборы не пересекаются по именам; число записей зависит от перемешивания групп. Затем строим словарь только по train и создаём контексты отдельно для каждого набора. Неизвестная в train буква в dev/test приводит к ошибке, а не расширяет словарь. Совпадения коротких контекстов у разных имён допустимы.

## 2. Lookup вместо one-hot

Таблица эмбеддингов `C` имеет форму `(27,10)`. Строка `C[i]` — обучаемые координаты символа i. Умножение one-hot вектора длины 27 на C даёт ту же строку, но прямой lookup не тратит вычисления на нули. `C[X]` для мини-батча даёт `(B,3,10)`. Координаты трёх символов объединяются в `(B,30)` с сохранением их порядка.

В программе создаётся одна модель: она обучается и генерирует имена. Отдельная маленькая модель из вводных ячеек notebook не запускается.

## 3. Полная модель

| Тензор | Форма | Параметров |
|---|---|---:|
| C | 27 × 10 | 270 |
| W1 | 30 × 200 | 6000 |
| b1 | 200 | 200 |
| W2 | 200 × 27 | 5400 |
| b2 | 27 | 27 |
| Всего | | **11 897** |

Прямой проход: `emb = C[X]`, `x = flatten(emb)`, `h = tanh(x W1 + b1)`, `logits = h W2 + b2`. Для B=32 формы: `(32,3,10) → (32,30) → (32,200) → (32,27)`. Смещения прибавляются к каждой строке. `tanh` нужен для нелинейности; два линейных слоя без него можно свернуть в один.

По умолчанию все пять тензоров инициализируются стандартными нормальными числами, как по смыслу в notebook. В программе один генератор с seed 42: после перемешивания групп имён он продолжает ту же последовательность для инициализации, выбора батчей и генерации имён. Большие начальные logits дают большую начальную ошибку; здесь намеренно сохранена исходная инициализация, без добавления BatchNorm или Adam.

Для эмбеддингов C сохранена альтернатива `initialize_embeddings_regular_cube`: при 27 символах она создаёт все узлы решётки 3 × 3 × 3 с координатами `-sqrt(3), 0, sqrt(3)` в первых трёх осях. Остальные семь координат сначала нулевые, затем обучаются. Для включения установи `USE_REGULAR_CUBE_EMBEDDINGS = true`; по умолчанию остаётся нормальная инициализация. Нормальная C создаётся в обоих режимах, поэтому выбор куба не меняет случайные числа остальных начальных весов.

Cross-entropy для одного примера:

```text
m = max(logits)
loss = m - logits[target] + ln(sum(exp(logits - m)))
```

Это та же `-ln(probability_of_correct_character)`, но без переполнения `exp` и без `ln(0)`. Loss усредняется по примерам; случайное равномерное предсказание даёт `ln(27) ≈ 3.296`.

## 4. Обратный проход и SGD

Весь Rust-код урока находится внутри функции `main` в `src/main.rs`, включая определения типов, реализации трейтов и численные вычисления. Открой блок расчёта градиентов внутри цикла обучения. Вместо `loss.backward()` здесь явно записано правило цепочки:

```text
dlogits = (softmax(logits) - one_hot(Y)) / B
dW2 = hᵀ dlogits                  db2 = sum_rows(dlogits)
dh = dlogits W2ᵀ
da = dh * (1 - h²)
dW1 = xᵀ da                       db1 = sum_rows(da)
dx = da W1ᵀ
dC[буква] += соответствующие координаты dx
```

Последний `+=` принципиален: одна буква может встретиться несколько раз внутри контекста и в разных примерах мини-батча. Все вклады должны сложиться. На каждом шаге выделяются нулевые градиенты. Все производные используют старые W1/W2, после чего локальный блок обновляет все параметры: `p -= lr * grad`.

Мини-батч содержит 32 случайных примера с возвращением. Выполняются 200 000 шагов: `lr=0.1` на шагах 0…99 999 и `lr=0.01` на остальных. Переменная `training_steps` сокращает или продлевает число шагов, но не переносит границу смены lr. Это число обновлений, а не эпох.

## 5. Качество, графики и генерация

После обучения считаем среднюю cross-entropy по **всему** train и dev без изменения параметров. По dev можно выбирать размер модели и скорость обучения. Test используется только для итоговой оценки: в notebook он подготовлен, но не оценён; здесь метрика дополнительно выводится. Не подбирай настройки по test.

Кривая `log10(loss)` шумит, поскольку каждый мини-батч другой; уменьшение lr обычно уменьшает шум. `embeddings.svg` показывает только координаты 0 и 1 десятимерного C — это не PCA и не полное расстояние между буквами. Близость на этой картинке может указывать на похожее использование букв, но не доказывает его во всех десяти измерениях.

Генерация начинает с `...`. Сеть выдаёт распределение вероятностей следующего символа, из него случайно выбирается индекс, контекст сдвигается, и процесс повторяется до точки. Это sampling, а не argmax: можно получить разные имена. Sampling использует общий генератор, продолжая последовательность после обучения. Изменение числа весов или шагов обучения меняет последующие случайные выборы. Ограничение 100 символов защищает от бесконечного вывода плохо обученной модели; усечённый результат явно помечается.

## Как читать имена в коде

В коде используются полные имена; короткие C, W1, b1, W2, b2 остаются в формулах для сверки с notebook.

| Имя в Rust | Значение |
|---|---|
| `vocabulary` / `vocabulary_size` | Словарь символов / число символов в нём |
| `vocabulary_context_indices` | Индексы трёх предыдущих букв |
| `vocabulary_character_index_target` | Индекс следующей буквы, которую нужно предсказать |
| `EMBEDDING_DIMENSIONS` | Число обучаемых координат одной буквы |
| `FIRST_LAYER_SIZE` | Число нейронов первого слоя |
| `character_embeddings` | Таблица координат букв, C |
| `character_embeddings_flattened` | Координаты трёх букв, объединённые в один вектор |
| `first_layer_weights`, `first_layer_biases` | W1 и b1: веса и смещения первого слоя |
| `first_layer_activations` | Выходы нейронов первого слоя после tanh |
| `second_layer_weights`, `second_layer_biases` | W2 и b2: веса и смещения второго слоя |
| `character_scores` | Logits: оценки букв до преобразования в вероятности |
| `character_probabilities` | Вероятности букв после softmax |
| `training_examples`, `validation_examples`, `test_examples` | Примеры для обучения, выбора настроек и окончательной оценки |
| `training_batch` | Мини-батч: группа примеров для одного обновления весов |
| `learning_rate` | Скорость обучения: множитель при вычитании градиента |
| `score_gradients` | Производные ошибки по выходным оценкам букв |
| `first_layer_pre_activation_gradients` | Производные ошибки по суммам первого слоя до tanh |
| `first_layer_weight_gradients` | Производные ошибки по весам W1 |
| `input_coordinate_gradient` | Производная ошибки по одной координате входного вектора |

Суффикс `_index` обозначает позицию, `_count` — количество, `_gradients` — производные ошибки по соответствующим значениям. `Model` хранит C, W1, b1, W2 и b2 в отдельных именованных полях. `ModelGradients` содержит соответствующие производные; шаг SGD явно связывает каждое поле модели с его градиентами. Длина контекста задаётся `CONTEXT_LENGTH = 3` и используется в типе контекста, размерах W1, подготовке примеров и генерации. Размеры эмбеддинга и первого слоя заданы константами `EMBEDDING_DIMENSIONS = 10` и `FIRST_LAYER_SIZE = 200`. W1 хранится как `[[FiniteF32; FIRST_LAYER_SIZE]; CONTEXT_LENGTH * EMBEDDING_DIMENSIONS]`, b1 — как `[FiniteF32; FIRST_LAYER_SIZE]`. C имеет тип `NonEmptyVec<[FiniteF32; EMBEDDING_DIMENSIONS]>`, W2 — `NonEmptyVec<[FiniteF32; FIRST_LAYER_SIZE]>` (один массив весов на выходной символ), b2 — `NonEmptyVec<FiniteF32>`. Градиенты повторяют формы параметров: `ModelGradients<f32>` используется при накоплении, а `ModelGradients<FiniteF32>` — после проверки перед шагом SGD. Число строк C, W2 и b2 задаётся размером словаря при инициализации; преобразования сохраняют эти длины. Число скалярных параметров учитывает обе размерности матриц. Вход первого слоя, его активации и градиенты — массивы фиксированной длины; мини-батч имеет тип `[VocabularyContextAndTargetIndices; BATCH_SIZE]` при `BATCH_SIZE = 32`.

## Проверка входных данных через типы

Вместо входных `assert!` используются типы с проверяемым созданием через `TryFrom` или методы словаря:

- `NonZeroUsize::new(число)` вместе с `ok_or(...)?` проверяет положительное число шагов.
- `Vocabulary` хранит уникальные буквы в алфавитном порядке и точку под индексом 0. `new` строит словарь из текста, `len` возвращает его размер, `dot_index` возвращает индекс точки для границ имени и начального контекста, `index_of` находит индекс символа, `character` возвращает символ с проверкой границ. `[VocabularyCharacterIndex; CONTEXT_LENGTH]` хранит индексы символов контекста; целевой символ имеет тот же тип. Числовой индекс создаётся через `VocabularyCharacterIndex::try_from((число, &vocabulary))`: допустимы значения от 0 до `vocabulary.len() - 1`. Поле `.0` содержит число для обращения к тензорам. Все типы находятся в одном модуле, поэтому приватность поля не запрещает прямой конструктор внутри `main.rs`; рабочий код создаёт числовые индексы через `TryFrom`. Проверка относится к словарю при создании; сам индекс не хранит его идентичность.
- `Name::try_from(строка)` принимает одно непустое имя из a–z. Исходный список, группы и выборки содержат проверенные `Name`, а непустота коллекций выражена `NonEmptyVec`.
- `NonEmptySlice::try_from(срез)` проверяет непустой срез без копирования: его используют обучающие примеры и входные оценки `cross_entropy`.
- `NonEmptyVec<CharacterProbabilityAsF32From0To1>` — непустой вектор вероятностей в результате `cross_entropy`. Проверка `TryFrom` отклоняет пустой вектор, доступ через срез не позволяет удалить элементы; `IntoIterator` генерируется через `derive_more`. Метод `map` сохраняет число элементов и непустоту при преобразовании, например вероятностей в градиенты. `Deref<Target = [T]>` генерируется через `#[derive(derive_more::Deref)]` с `#[deref(forward)]`.

Ошибки возвращаются строками `&'static str` и передаются вызывающему коду через `?`. Непустота закреплена также в наборах имён после разделения, примерах, параметрах и градиентах модели, выходных оценках, координатах эмбеддингов и готовой кривой обучения. Обычный `Vec` остаётся для временных накопителей, которые действительно бывают пустыми при построении. Проверка `Name` запрещает пустое имя и символы вне a–z. `NonEmptyVec` не реализует `DerefMut`: изменение численных элементов выполняется через `.0` без изменения длины. Как и у индексов, локальные определения внутри `main` не защищают от прямого обхода конструктора самим кодом урока.

`CrossEntropyLossAsNonNegativeF32` проверяет конечность и неотрицательность как отдельного, так и среднего loss. Вероятности проверяются на диапазон `[0, 1]`. `FiniteF32` хранит конечное число: этот тип используют параметры `Model`, поля `ForwardPassResult`, готовые градиенты и координаты графиков. Проверки выполняются при инициализации, завершении вычислений и обновлении параметров; промежуточная арифметика остаётся на `f32`. Скорость обучения имеет тип `LearningRateAsPositiveFiniteF32`, запрещающий также ноль и отрицательные значения. Веса, координаты и градиенты могут быть отрицательными, поэтому ограничение вероятностей к ним неприменимо. График принимает `PlotData`: `Line` содержит непустой срез координат, а `LabeledPoints` — непустой срез `(char, FiniteF32, FiniteF32)`. Подпись хранится вместе с точкой, поэтому несовпадение длин невозможно. `From<&NonEmptyVec<T>>` для `NonEmptySlice<T>` заимствует уже проверенные данные без повторной проверки непустоты. `derive_where` генерирует `Copy` и `Clone` для `NonEmptySlice` без лишних ограничений на элементы.

## Локальная область видимости

Единственное определение верхнего уровня в `src/main.rs` — функция `main`. Весь код, структуры и реализации трейтов находятся внутри неё; объявлений `mod`, `use` и дополнительных Rust-файлов нет. Общие типы индекса, контекста, обучающего примера и непустого среза доступны этапам внутри `main`. `Vocabulary` объявлен в блоке подготовки данных, `Name` — в блоке подготовки данных. Типы вероятности, loss и непустого вектора доступны внутри `main`; `Model` — блоку создания модели и замыканий `forward`/`loss`; `ModelGradients` — одному расчёту градиентов. Значения локальных типов передаются между этапами с выводом типов, без расширения области их определений. Полные пути стандартной библиотеки, `rand` и `rand_distr` указаны непосредственно в местах обращения, без `use`. Методы трейтов вызываются явно: например, `rand::RngExt::random(&mut random_generator)` и `rand_distr::Distribution::sample(&rand_distr::StandardNormal, &mut random_generator)`. `Name` и его реализации доступны только блоку подготовки данных. Число шагов хранится непосредственно в `std::num::NonZeroUsize`, без дополнительной обёртки. Модель создаётся локальным блоком с инициализацией параметров из нормального распределения. Замыкание `build_vocabulary_context_and_target_indices` находится в блоке подготовки данных, захватывает словарь и возвращает `Result`, отклоняя неизвестные символы; Cross-entropy вычисляет замыкание `cross_entropy`. Замыкания `forward` и `loss` получают модель аргументом; размер словаря `vocabulary_len` вычисляется один раз через `vocabulary.len()`, формы выхода `forward` определяются полями модели. В `Model` нет копии размера словаря или ссылки на него. Функция `plot` определена внутри `main` рядом с обучением и выводом результатов.

Сборка проверяется через `cargo check`; обучение запускается через `cargo run`.

## Подготовка файлов

До подготовки данных и обучения один блок создаёт каталог и открывает все нужные файлы. Дескрипторы сохраняются в `files: std::collections::BTreeMap<String, std::fs::File>`. Дальше этапы забирают свои файлы через `remove` и только записывают в них. `plot` принимает открытый файл. Для loss применяется `BufWriter` поверх уже открытого файла.

Создаются шесть файлов. Повторный запуск сразу перезаписывает подготовленный набор файлов.

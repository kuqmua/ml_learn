## 1. Словарь и задача предсказания

В `data/names.txt` 32 033 имени. Буквы a–z получают индексы 1–26, точка — 0. Точка означает и пустой начальный контекст, и конец имени. Для `emma` получаются:

| Контекст X | Цель Y |
|---|---|
| `...` | `e` |
| `..e` | `m` |
| `.em` | `m` |
| `emm` | `a` |
| `mma` | `.` |

Каждая строка X — три целых индекса, Y — один индекс. Всего 228 146 примеров. Контекст сбрасывается между именами: последнее имя не подсказывает начало следующего. Сначала объединяем одинаковые имена в группы, перемешиваем **группы** с seed 42 и выделяем 80% уникальных имён в train, 10% в dev и 10% в test. Все копии одного имени остаются в одном наборе; частоты и все 32 033 записи сохраняются. Получается 25 639 / 3 186 / 3 208 записей (23 595 / 2 949 / 2 950 уникальных имён), без пересечений. Затем строим словарь только по train и создаём контексты отдельно для каждого набора. Неизвестная в train буква в dev/test приводит к ошибке, а не расширяет словарь. Совпадения коротких контекстов у разных имён допустимы.

## 2. Lookup вместо one-hot

Таблица эмбеддингов `C` имеет форму `(27,10)`. Строка `C[i]` — обучаемые координаты символа i. Умножение one-hot вектора длины 27 на C даёт ту же строку, но прямой lookup не тратит вычисления на нули. `C[X]` для мини-батча даёт `(B,3,10)`. Координаты трёх символов объединяются в `(B,30)` с сохранением их порядка.

В программе создаётся одна модель: она обучается и генерирует имена. Отдельная маленькая модель из вводных ячеек notebook не запускается.

## 3. Полная модель

| Тензор | Форма | Параметров |
|---|---|---:|
| C | 27 × 10 | 270 |
| W1 | 30 × 200 | 6000 |
| b1 | 200 | 200 |
| W2 | 200 × 27 | 5400 |
| b2 | 27 | 27 |
| Всего | | **11 897** |

Прямой проход: `emb = C[X]`, `x = flatten(emb)`, `h = tanh(x W1 + b1)`, `logits = h W2 + b2`. Для B=32 формы: `(32,3,10) → (32,30) → (32,200) → (32,27)`. Смещения прибавляются к каждой строке. `tanh` нужен для нелинейности; два линейных слоя без него можно свернуть в один.

По умолчанию все пять тензоров инициализируются независимыми стандартными нормальными числами с seed 2147483647, как по смыслу в notebook. Большие начальные logits дают большую начальную ошибку; здесь намеренно сохранена исходная инициализация, без добавления BatchNorm или Adam.

Для эмбеддингов C сохранена альтернатива `initialize_embeddings_regular_cube`: при 27 символах она создаёт все узлы решётки 3 × 3 × 3 с координатами `-sqrt(3), 0, sqrt(3)` в первых трёх осях. Остальные семь координат сначала нулевые, затем обучаются. Для включения установи `USE_REGULAR_CUBE_EMBEDDINGS = true`; по умолчанию остаётся нормальная инициализация. Нормальная C создаётся в обоих режимах, поэтому выбор куба не меняет случайные числа остальных начальных весов.

Cross-entropy для одного примера:

```text
m = max(logits)
loss = m - logits[target] + ln(sum(exp(logits - m)))
```

Это та же `-ln(probability_of_correct_character)`, но без переполнения `exp` и без `ln(0)`. Loss усредняется по примерам; случайное равномерное предсказание даёт `ln(27) ≈ 3.296`.

## 4. Обратный проход и SGD

Весь код урока находится внутри `main` в `src/main.rs`: численные функции и структуры локальны для неё, проверяемые типы также объявлены непосредственно внутри `main`. Открой блок расчёта градиентов внутри цикла обучения. Вместо `loss.backward()` здесь явно записано правило цепочки:

```text
dlogits = (softmax(logits) - one_hot(Y)) / B
dW2 = hᵀ dlogits                  db2 = sum_rows(dlogits)
dh = dlogits W2ᵀ
da = dh * (1 - h²)
dW1 = xᵀ da                       db1 = sum_rows(da)
dx = da W1ᵀ
dC[буква] += соответствующие координаты dx
```

Последний `+=` принципиален: одна буква может встретиться несколько раз внутри контекста и в разных примерах мини-батча. Все вклады должны сложиться. На каждом шаге выделяются нулевые градиенты. Все производные используют старые W1/W2, после чего локальный блок обновляет все параметры: `p -= lr * grad`.

Мини-батч содержит 32 случайных примера с возвращением. Выполняются 200 000 шагов: `lr=0.1` на шагах 0…99 999 и `lr=0.01` на остальных. Переменная `training_steps` сокращает или продлевает число шагов, но не переносит границу смены lr. Это число обновлений, а не эпох.

## 5. Качество, графики и генерация

После обучения считаем среднюю cross-entropy по **всему** train и dev без изменения параметров. По dev можно выбирать размер модели и скорость обучения. Test используется только для итоговой оценки: в notebook он подготовлен, но не оценён; здесь метрика дополнительно выводится. Не подбирай настройки по test.

Кривая `log10(loss)` шумит, поскольку каждый мини-батч другой; уменьшение lr обычно уменьшает шум. `embeddings.svg` показывает только координаты 0 и 1 десятимерного C — это не PCA и не полное расстояние между буквами. Близость на этой картинке может указывать на похожее использование букв, но не доказывает его во всех десяти измерениях.

Генерация начинает с `...`. Сеть выдаёт распределение вероятностей следующего символа, из него случайно выбирается индекс, контекст сдвигается, и процесс повторяется до точки. Это sampling, а не argmax: можно получить разные имена. Генератор для sampling имеет отдельный seed 2147483657. Ограничение 100 символов защищает от бесконечного вывода плохо обученной модели; усечённый результат явно помечается.

## Как читать имена в коде

В коде используются полные имена; короткие C, W1, b1, W2, b2 остаются в формулах для сверки с notebook.

| Имя в Rust | Значение |
|---|---|
| `vocabulary` / `vocabulary_size` | Словарь символов / число символов в нём |
| `vocabulary_context_indices` | Индексы трёх предыдущих букв |
| `vocabulary_character_index_target` | Индекс следующей буквы, которую нужно предсказать |
| `EMBEDDING_DIMENSIONS` | Число обучаемых координат одной буквы |
| `HIDDEN_NEURON_COUNT` | Число нейронов скрытого слоя |
| `character_embeddings` | Таблица координат букв, C |
| `flattened_embeddings` | Координаты трёх букв, объединённые в один вектор |
| `input_to_hidden_weights`, `hidden_biases` | W1 и b1: веса и смещения скрытого слоя |
| `hidden_activations` | Выходы скрытых нейронов после tanh |
| `hidden_to_output_weights`, `output_biases` | W2 и b2: веса и смещения выходного слоя |
| `character_scores` | Logits: оценки букв до преобразования в вероятности |
| `character_probabilities` | Вероятности букв после softmax |
| `training_examples`, `validation_examples`, `test_examples` | Примеры для обучения, выбора настроек и окончательной оценки |
| `training_batch` | Мини-батч: группа примеров для одного обновления весов |
| `learning_rate` | Скорость обучения: множитель при вычитании градиента |
| `score_gradients` | Производные ошибки по выходным оценкам букв |
| `hidden_pre_activation_gradients` | Производные ошибки по суммам скрытого слоя до tanh |
| `input_to_hidden_weight_gradients` | Производные ошибки по весам W1 |
| `input_coordinate_gradient` | Производная ошибки по одной координате входного вектора |

Суффикс `_index` обозначает позицию, `_count` — количество, `_gradients` — производные ошибки по соответствующим значениям. `Model` хранит C, W1, b1, W2 и b2 в отдельных именованных полях. `ModelGradients` содержит соответствующие производные; шаг SGD явно связывает каждое поле модели с его градиентами. Длина контекста задаётся `CONTEXT_LENGTH = 3` и используется в типе контекста, размерах W1, подготовке примеров и генерации. Размеры эмбеддинга и скрытого слоя заданы константами `EMBEDDING_DIMENSIONS = 10` и `HIDDEN_NEURON_COUNT = 200`. W1 и b1, включая их градиенты, хранятся в массивах фиксированной длины; C хранится как `Vec<[f32; EMBEDDING_DIMENSIONS]>`: каждый элемент — эмбеддинг одного символа; его градиенты имеют ту же форму. W2 и b2 остаются `Vec<f32>`, поскольку зависят от размера словаря. Число параметров вычисляется один раз: для C число строк умножается на `EMBEDDING_DIMENSIONS`, затем добавляются длины остальных тензоров.

## Проверка входных данных через типы

Вместо входных `assert!` используются локальные типы с проверяемым созданием через `TryFrom` или методы словаря:

- `NonZeroUsize::new(число)` вместе с `ok_or(...)?` проверяет положительное число шагов.
- `Vocabulary` хранит уникальные буквы в алфавитном порядке и точку под индексом 0. `new` строит словарь из текста, `len` возвращает его размер, `dot_index` возвращает индекс точки для границ имени и начального контекста, `index_of` находит индекс символа, `character_index` проверяет числовой индекс, `character` возвращает символ с проверкой границ. `VocabularyContextIndices` хранит три `VocabularyCharacterIndex`; целевой символ имеет тот же тип.
- `Names::try_from(текст)` принимает непустой список непустых имён из a–z. Локальный блок перемешивания меняет только порядок и сохраняет проверенный тип.
- `NonEmptySlice::try_from(срез)` проверяет непустой набор примеров без копирования данных. замыкание `loss` и локальный расчёт градиентов используют именно этот тип.

Ошибки возвращаются строками `&'static str` и передаются вызывающему коду через `?`. После создания типа проверки не повторяются внутри численных методов. Изменяемого доступа к внутреннему срезу нет.

## Подготовка файлов

До подготовки данных и обучения один блок создаёт каталог и открывает все нужные файлы. Дескрипторы сохраняются в `files: std::collections::BTreeMap<String, std::fs::File>`. Создаются шесть файлов. Повторный запуск сразу перезаписывает подготовленный набор файлов.

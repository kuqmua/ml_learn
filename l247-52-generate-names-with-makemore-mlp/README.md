## 1. Словарь и задача предсказания

В `data/names.txt` 32 033 имени. Буквы a–z получают индексы 1–26, точка — 0. Точка означает и пустой начальный контекст, и конец имени. Для `emma` получаются:

| Контекст X | Цель Y |
|---|---|
| `...` | `e` |
| `..e` | `m` |
| `.em` | `m` |
| `emm` | `a` |
| `mma` | `.` |

Каждая строка X — три целых индекса, Y — один индекс. После удаления копий всего 211 328 примеров. Контекст сбрасывается между именами: последнее имя не подсказывает начало следующего. Сначала удаляем одинаковые имена через `BTreeSet`: из 32 033 строк остаётся 29 494 уникальных имени. Перемешиваем их с seed 42 и выделяем 80% в train, 10% в dev и 10% в test. Каждое имя используется один раз и только в одном наборе. Затем строим словарь только по train и создаём контексты отдельно для каждого набора. Неизвестная в train буква в dev/test приводит к ошибке, а не расширяет словарь. Совпадения коротких контекстов у разных имён допустимы.

## 2. Lookup вместо one-hot

Таблица эмбеддингов `C` имеет форму `(27,8)`. Строка `C[i]` — фиксированные координаты символа i. Умножение one-hot вектора длины 27 на C даёт ту же строку, но прямой lookup не тратит вычисления на нули. `C[X]` для мини-батча даёт `(B,3,8)`. Координаты трёх символов объединяются в `(B,24)` с сохранением их порядка.

В программе создаётся одна модель: она обучается и генерирует имена. Отдельная маленькая модель из вводных ячеек notebook не запускается.

## 3. Полная модель

По итогам бенчмарка выбраны embedding=8 и first_layer=64: 3571 хранимый коэффициент (из них 3355 обучаются),
28 568 байт (27.90 КиБ): параметры FP32 — 14 284, градиенты FP32 — 14 284. Это полезные данные массивов, включая замороженные эмбеддинги, без контейнеров, выравнивания и активаций. Для предсказания сами параметры FP32 занимают 14 284 байта; дополнительной вычислительной копии нет.

| Тензор | Форма | Параметров |
|---|---|---:|
| C | 27 × 8 | 216 |
| W1 | 24 × 64 | 1536 |
| b1 | 64 | 64 |
| W2 | 64 × 27 | 1728 |
| b2 | 27 | 27 |
| Всего | | **3 571** |

Прямой проход: `emb = C[X]`, `x = flatten(emb)`, `h = SiLU(x W1 + b1)`, `logits = h W2 + b2`. Для B=32 формы: `(32,3,8) → (32,24) → (32,64) → (32,27)`. Смещения прибавляются к каждой строке. `SiLU` нужна для нелинейности; два линейных слоя без него можно свернуть в один.

По умолчанию C — фиксированный куб ±1, а веса и смещения обоих слоёв инициализируются StandardNormal. После подготовки данных генератор заново получает seed 42 для инициализации модели: это воспроизводит выбранный бенчмарк. Батчи обходятся последовательно без расходования случайных чисел. После инициализации генератор используется для генерации имён.

`initialize_embeddings_regular_cube` заполняет все восемь координат. Для 27 символов выбираются вершины с номерами `i * 255 / 26`; каждый элемент равен −1 или +1. По умолчанию `USE_REGULAR_CUBE_EMBEDDINGS = true`, `REGULAR_CUBE_HALF_WIDTH_SQUARED = 1.0`, `FREEZE_EMBEDDINGS = true`. Нормальная таблица C всё равно генерируется перед выбором ветки, сохраняя последовательность случайных чисел для остальных параметров. При `FREEZE_EMBEDDINGS = false` таблица снова обучается.

Cross-entropy для одного примера:

```text
m = max(logits)
loss = m - logits[target] + ln(sum(exp(logits - m)))
```

Это та же `-ln(probability_of_correct_character)`, но без переполнения `exp` и без `ln(0)`. Loss усредняется по примерам; случайное равномерное предсказание даёт `ln(27) ≈ 3.296`.

## 4. Обратный проход и SGD

Исходная CPU-реализация находится внутри функции `main` в `src/main.rs`, включая определения типов, реализации трейтов и численные вычисления. Открой блок расчёта градиентов внутри цикла обучения. Вместо `loss.backward()` здесь явно записано правило цепочки:

```text
dlogits = (softmax(logits) - one_hot(Y)) / B
dW2 = hᵀ dlogits                  db2 = sum_rows(dlogits)
dh = dlogits W2ᵀ
s = sigmoid(a)                   # a = x W1 + b1
da = dh * (s + a * s * (1 - s))
dW1 = xᵀ da                       db1 = sum_rows(da)
dx = da W1ᵀ                     # только если FREEZE_EMBEDDINGS = false
dC[буква] += соответствующие координаты dx  # только в обучаемом режиме
```

При обучаемой C последний `+=` принципиален: одна буква может встретиться несколько раз внутри контекста и в разных примерах мини-батча. Все вклады должны сложиться. Перед батчем накопители градиентов весов и смещений обнуляются на месте. Все производные используют старые W1/W2. Затем обновляются веса и смещения: `p -= lr * grad`. При фиксации C её градиенты остаются нулевыми, а таблица не обновляется.

Обучающие примеры берутся последовательно батчами по 32 без перемешивания между эпохами. Последний батч может быть короче: каждый пример используется ровно один раз за эпоху. После конца набора следующий проход начинается с начала в том же порядке. Выполняются 125 000 шагов: `lr=0.1` на шагах 0…99 999 и `lr=0.01` на остальных. Константа `TRAINING_STEPS` сокращает или продлевает число шагов; граница смены lr задаётся отдельно в `LEARNING_RATE_CHANGE_STEP`. Это число обновлений, а не эпох.

## 5. Качество и генерация

После обучения считаем среднюю cross-entropy по **всему** train и dev без изменения параметров. По dev можно выбирать размер модели и скорость обучения. Test используется только для итоговой оценки: в notebook он подготовлен, но не оценён; здесь метрика дополнительно вычисляется. Не подбирай настройки по test.

Loss отдельных мини-батчей колеблется, поскольку на каждом шаге выбираются другие примеры. Итоговые train/dev/test loss считаются по полным наборам и сохраняются в локальном массиве `_losses`.

Генерация начинает с `...`. Сеть выдаёт распределение вероятностей следующего символа, из него случайно выбирается индекс, контекст сдвигается, и процесс повторяется до точки. Это sampling, а не argmax: можно получить разные имена. Sampling использует общий генератор, продолжая последовательность после обучения. Изменение числа весов или шагов обучения меняет последующие случайные выборы. Ограничение 100 символов защищает от бесконечной генерации плохо обученной модели; усечённый результат явно помечается.

## Прямой проход, обратный проход и шаг обучения

В пояснениях ниже `forward` и `backward` — сокращённые названия длинных методов прямого и обратного проходов в исходнике.

`Model` хранит параметры и накопители градиентов в одном объекте. `overwrite_gradients_with_zeros(&mut self)` обнуляет градиенты весов и смещений перед батчем; градиенты C — только в обучаемом режиме, сохраняя выделенную память. `forward_pass(&self, previous_vocabulary_character_usize_indexes)` вычисляет предсказание и сохраняет промежуточные значения в `PreviousCharactersEmbeddingsFlattenedAndFirstAndSecondLayerOutputs`. `backward(&mut self, forward_result, score_gradients)` накапливает производные в поля градиентов модели, не изменяя параметры. `step(&mut self, learning_rate)` обновляет параметры по накопленным градиентам после обработки всего батча.

Порядок вызовов: `model.overwrite_gradients_with_zeros()?` → для каждого примера `model.forward(...)`, `SoftmaxCrossEntropy::forward(...)`, `SoftmaxCrossEntropy::backward(...)`, `model.backward(...)` → один `model.step(learning_rate)?`. `backward` добавляет вклад каждого примера; обнуление внутри этого цикла уничтожило бы вклады предыдущих примеров. `step` оставляет градиенты доступными для просмотра, а следующий `overwrite_gradients_with_zeros` очищает их.

| Операция | `forward` | `backward` |
|---|---|---|
| `Model` | Контекст → эмбеддинги → первый слой → `SiLU` → оценки символов | Градиенты оценок → второй слой → `SiLU` → первый слой → эмбеддинги |
| `SoftmaxCrossEntropy` | Оценки и правильный символ → вероятности и ошибка | Вероятности и правильный символ → `(p − target) / batch_len` |
| `Silu` | `output = SiLU(input)` | `input_gradient = output_gradient × (s + input × s × (1 − s)), s = sigmoid(input)` |

`backward` не восстанавливает вход из выхода. Он передаёт производную ошибки назад по правилу цепочки. Градиентный спуск — следующий, отдельный этап `Model::step`: `parameter -= learning_rate * gradient`.

В цикле обучения сначала вызываются `model.forward(...)` и `SoftmaxCrossEntropy::forward(...)`. Далее комментарии ограничивают backpropagation: `SoftmaxCrossEntropy::backward(...)` и `model.backward(...)`. Внутри `Model::backward` градиенты весов и смещений изменяются в отдельных блоках; блок C выполняется только при `FREEZE_EMBEDDINGS = false`. Между градиентами второго и первого слоёв вызывается `Silu::backward_input_gradient(...)`. После завершения батча выполняется один `model.step(...)`.

`PreviousCharactersEmbeddingsFlattenedAndFirstAndSecondLayerOutputs` хранит объединённые эмбеддинги, входы SiLU и выходы обоих слоёв. Входы SiLU нужны для её производной: восстановить их по выходам однозначно нельзя. Для `backward` используется результат того же прямого прохода; между этими вызовами параметры не меняются. При создании `Model` в `main` накопители градиентов заполняются нулями. Перед каждым батчем `Model::overwrite_gradients_with_zeros` обнуляет их на месте. При генерации имён используется только `forward`; градиенты остаются в модели, но не участвуют в предсказании. Размер батча передаётся в `SoftmaxCrossEntropy::backward` как `NonZeroUsize`, поэтому деление на ноль исключено; усреднение выполняется ровно один раз.

## Проверка входных данных через типы

Вместо входных `assert!` используются типы с проверяемым созданием через `TryFrom` или методы словаря:

- `NonZeroUsize::new(число)` вместе с `ok_or(...)?` проверяет положительное число шагов.
- `Vocabulary` хранит уникальные буквы в алфавитном порядке и точку под индексом 0. `new` строит словарь из текста, `len` возвращает его размер, `dot_index` возвращает индекс точки для границ имени и начального контекста, `index_of` находит индекс символа, `character` возвращает символ с проверкой границ. `[VocabularyCharacterIndexAsUsize; PREVIOUS_CHARACTER_COUNT_FOR_NEXT_CHARACTER_PREDICTION]` хранит индексы символов контекста; целевой символ имеет тот же тип. Числовой индекс создаётся через `VocabularyCharacterIndexAsUsize::try_from((число, &vocabulary))`: допустимы значения от 0 до `vocabulary.len() - 1`. Поле `.0` содержит число для обращения к тензорам. Типы находятся в `src/main.rs`; прямой конструктор внутри того же модуля по-прежнему возможен; рабочий код создаёт числовые индексы через `TryFrom`. Проверка относится к словарю при создании; сам индекс не хранит его идентичность.
- `Name::try_from(строка)` принимает одно непустое имя из a–z. Исходный список, уникальные имена и выборки содержат проверенные `Name`, а непустота коллекций выражена `NonEmptyVec`.
- `NonEmptySlice::try_from(срез)` проверяет непустой срез без копирования: его используют обучающие примеры и входные оценки `SoftmaxCrossEntropy::forward`.
- `NonEmptyVec<CharacterProbabilityAsF32From0To1>` — непустой вектор вероятностей в результате `SoftmaxCrossEntropy::forward`. Проверка `TryFrom` отклоняет пустой вектор, доступ через срез не позволяет удалить элементы; `IntoIterator` генерируется через `derive_more`. Метод `map` сохраняет число элементов и непустоту при преобразовании, например вероятностей в градиенты. `Deref<Target = [T]>` генерируется через `#[derive(derive_more::Deref)]` с `#[deref(forward)]`.

Ошибки возвращаются строками `&'static str` и передаются вызывающему коду через `?`. Непустота закреплена также в наборах имён после разделения, примерах, параметрах и градиентах модели и выходных оценках. Обычный `Vec` остаётся для временных накопителей, которые действительно бывают пустыми при построении. Проверка `Name` запрещает пустое имя и символы вне a–z. `NonEmptyVec` не реализует `DerefMut`: изменение численных элементов выполняется через `.0` без изменения длины. Как и у индексов, доступность полей внутри того же модуля не защищает от прямого обхода конструктора самим кодом урока.

`second_layer_biases_gradients` хранит `SecondLayerBiasGradientAsF32FromMinus1To1`: после обнуления сумма вкладов `(p - y) / N` одного батча математически лежит в `[-1, 1]`. При накоплении проверяется диапазон; отклонение до `(BATCH_SIZE + 2) × f32::EPSILON` за границей считается погрешностью округления и прижимается к границе. Внутри обёртки всегда хранится конечное число строго в `[-1, 1]`. Большие отклонения возвращают ошибку. Остальные градиенты остаются `FiniteF32`, поскольку умножаются на веса, активации и производные.

`CrossEntropyLossAsNonNegativeF32` проверяет конечность и неотрицательность как отдельного, так и среднего loss. Вероятности проверяются на диапазон `[0, 1]`. `FiniteF32` хранит конечные параметры, сохранённые активации и накопители градиентов. Проверки выполняются при инициализации, завершении вычислений и обновлении параметров; промежуточная арифметика остаётся на `f32`. Скорость обучения имеет тип `LearningRateAsPositiveFiniteF32`, запрещающий также ноль и отрицательные значения. Веса, координаты и градиенты могут быть отрицательными, поэтому ограничение вероятностей к ним неприменимо. `From<&NonEmptyVec<T>>` для `NonEmptySlice<T>` заимствует уже проверенные данные без повторной проверки непустоты. `derive_where` генерирует `Copy` и `Clone` для `NonEmptySlice` без лишних ограничений на элементы.

## Порядок чтения кода

`src/main.rs` читается сверху вниз: константы → `main` с подготовкой данных, созданием модели, обучением, оценкой и генерацией → `Model` с методами `forward_pass`, `overwrite_gradients_with_zeros`, `backward_pass`, `step` → `Silu` и `SoftmaxCrossEntropy` → типы данных и проверяющие обёртки → `try_map_array`. Каждый тип расположен рядом со своими блоками `impl`. Замыкание `loss` объявлено в `main` непосредственно перед первой оценкой модели. JSON-комментарии находятся только внутри `main`. Отдельного модуля типов нет.

Модель создаётся локальным блоком: C заполняется фиксированным кубом, остальные параметры — нормальными случайными числами. Замыкание `build_previous_vocabulary_character_indexes_and_next_character_indexes` локально блоку подготовки данных и захватывает словарь. Замыкание `loss` использует `Model::forward` и `SoftmaxCrossEntropy::forward` для оценки выборки. Генерация имён использует те же прямые операции без `backward` и `step`. Размеры выходных массивов методов определяются полями модели; `Model` не хранит копию размера словаря или ссылку на него. Вспомогательные функции накопления локальны `Model::backward`, замыкание обновления среза — `Model::step`.

Полные пути стандартной библиотеки, `rand` и `rand_distr` указаны непосредственно в местах обращения; типы урока объявлены в том же файле. Число шагов хранится в `std::num::NonZeroUsize`.

Сборка проверяется через `cargo check`; обучение запускается через `cargo run`.

Локальные значения и кортежи имеют явные подписи типов. У замыканий явно указаны типы параметров и результата; их анонимный тип выводится Rust. В `for` Rust не допускает аннотацию типа у шаблона, поэтому тип элемента указан через `let` в начале тела цикла.

`NextCharacterScoreGradientAsF32FromMinus1To1` и `TargetScoreGradientAsF32FromMinus1To0` объявлены в `src/main.rs` и связывают `SoftmaxCrossEntropy::backward` с `Model::backward`. `NextCharacterScoreGradientAsF32FromMinus1To1` различает производные по оценкам следующего символа: `Target` содержит проверенный `TargetScoreGradientAsF32FromMinus1To0` в диапазоне [−1, 0], а `Other` использует проверенный диапазон [0, 1]. Значения уже поделены на фактический размер батча. При построении коллекции `Target` ставится только на позицию правильного символа; сам enum количество таких вариантов не ограничивает.

В каждой паре эмбеддинги, веса и смещения имеют одинаковые начальные значения.
Эмбеддинги — случайные восьмимерные векторы из StandardNormal; в режиме

### Геометрия фиксированного куба: расстояния, масштаб и назначение символам

Равномерный выбор **номеров** `i * 255 / 26` не максимизирует расстояния
между вершинами. Для вершин с координатами ±a квадрат евклидова расстояния
равен `4 * a² * h`, где h — число различающихся координат (расстояние Хэмминга).
У текущих 27 вершин семь пар с h=1: a–n, b–o, f–s, g–t, k–x, l–y, m–z.
При a=√3 минимальное расстояние равно 2√3. Диаметр куба равен 2√24,
но такое расстояние имеют только противоположные вершины.

В контрольном варианте жадный выбор каждый раз максимизирует минимальное
расстояние Хэмминга до уже выбранных точек. При равенстве выбирается большая
сумма расстояний, затем меньший номер вершины; первая вершина — 0.
Для 27 точек получено минимальное h=2: минимальное евклидово расстояние
увеличено в √2 раза при том же масштабе. Это проверенная эвристика,
а не доказанный глобально оптимальный набор. Индексы, распределения
расстояний и ближайшие пары сохранены в `geometry_theory.json`.

Максимизация расстояний требует ограничения масштаба: без него достаточно
умножать все координаты на любое большое число. Кроме того, 27 равноудалённых
различных точек требуют как минимум 26 измерений, а здесь их восемь.
Поэтому цель «все точки максимально далеко друг от друга» нужно уточнять,
например: максимизировать минимальное расстояние при фиксированной норме.

У куба ±√3 квадрат нормы каждой строки равен 8×3=24. У StandardNormal
математическое ожидание квадрата нормы равно 8; у куба ±1 он точно равен 8.
При конкатенации трёх строк и независимых начальных весах и смещении N(0,1)
дисперсия суммы перед tanh, условно по входу x, равна `||x||² + 1`.
Для куба ±√3 это 73, для куба ±1 — 25. У случайных эмбеддингов это 25
в среднем по их инициализации. Более крупные суммы чаще дают tanh около
−1 или +1, где производная `1 − tanh(z)²` мала. Это согласуется с анализом
масштаба инициализации и насыщения в работе
[Glorot & Bengio, 2010](https://proceedings.mlr.press/v9/glorot10a.html).

Смена масштаба влияет не только на насыщение. Если C=aB, то C W=B(aW):
масштаб можно поглотить весами, и класс представимых функций не меняется.
Но для V=aW шаг SGD превращается в шаг с эффективной скоростью ηa².
Поэтому сравнение масштабов при прежних W и learning rate измеряет общий
эффект инициализации и оптимизации; оно не выделяет насыщение как единственную причину.

Расстояния между фиксированными векторами сами по себе не оптимизируют
предсказание следующего символа. Для одной позиции входа вклад до tanh
задаётся матрицей C W, где C имеет размер 27×8: каждый столбец C W находится
в пространстве столбцов C. Обучение C позволяет менять это пространство под
данные; при фиксированной C оно задано заранее. Даже перестановка того же
набора точек между символами сохраняет все попарные расстояния как набор,
но меняет соответствие геометрии статистике имён. Нет общего математического
утверждения, что случайная таблица всегда лучше куба или наоборот.

Контрольный опыт: шесть вариантов × seed 42/43/44, по 200 000 шагов,
все эмбеддинги фиксированные. Веса и смещения при одном seed совпадают
побитно; данные и настройки обучения прежние. Варианты меняют масштаб,
выбор вершин или назначение тех же вершин символам. Диагностика насыщения
измеряется **до обучения** на каждом 41-м обучающем примере (264 000 выходов tanh),
порог — `abs(tanh) > 0.99`. Диагностика не расходует RNG и не входит во время обучения.

Средние по трём seed; после ± указано выборочное стандартное отклонение:

| Фиксированные эмбеддинги | Dev NLL | Test NLL | Насыщение tanh до обучения |
|---|---:|---:|---:|
| StandardNormal | 2.22696 ± 0.00295 | 2.21445 ± 0.00302 | 57.53% |
| Куб ±√3, текущие вершины | 2.24165 ± 0.00223 | 2.23661 ± 0.00073 | 75.66% |
| Куб ±1, те же вершины | 2.22887 ± 0.00023 | 2.21583 ± 0.00129 | 59.63% |

При уменьшении масштаба текущего куба test NLL снизился с 2.23661 до 2.21583:

Все таблицы имеют центрированный ранг 8, то есть результат не объясняется
возвращением к трём активным измерениям. В каждом запуске проверены 27 разных

опыте. Масштаб, распределение точек и их назначение символам — разные факторы.

### Функции активации при фиксированных эмбеддингах

Сравнение четырёх активаций для StandardNormal и куба ±1 с прежними вершинами
`i * 255 / 26`. Обе таблицы эмбеддингов фиксированы. Всего 24 полных запуска:
два представления × четыре активации × seed 42/43/44. Модель 8×64, 200 000
шагов, batch до 32, split seed 42 и SGD прежние: 0.1 первые 100 000 шагов,
затем 0.01. Начальные веса и смещения не масштабировались под активацию.
Это сравнение прямой замены функции при текущих настройках, а не лучших
возможных результатов после индивидуального подбора инициализации и SGD.

| Активация | Функция f(x) | Производная |
|---|---|---|
| tanh | tanh(x) | 1 − f(x)² |
| ReLU | max(0, x) | 1 при x > 0, иначе 0 |
| Leaky ReLU | x при x > 0, иначе 0.01x | 1 при x > 0, иначе 0.01 |
| SiLU | x σ(x), σ(x)=1/(1+exp(−x)) | σ(x) + x σ(x)(1−σ(x)) |

Для SiLU используется устойчивая к переполнению запись sigmoid с отдельными
ветвями по знаку x. В обратном проходе используются сохранённые суммы до
активации; восстановить вход только по выходу SiLU нельзя. Сохранение этих
сумм добавлено во все варианты, включая контрольный tanh. Его обратный
проход сохраняет прежний порядок вычислений через выход tanh.

Перед каждым запуском реализация производной проверяется центральной
конечной разностью с шагом 0.001 в точках −8, −2, −0.3, 0.3, 2, 8;

### Расширенная статистика активаций: 20 seed на каждый вариант

Объём расширен до 160 запусков: восемь вариантов × seed 42–61. Первые
24 проверенных лога (seed 42–44) перенесены из пилотной серии без повторного
обучения; дополнительно выполнены 136 запусков на seed 45–61. Те же снимки
исходников, данные, split, число шагов, инициализация и SGD; новых настроек
по ходу расширения не подбиралось. Каждый запуск — отдельная модель,
внутри одного seed начальные параметры совпадают между активациями,
а между представлениями совпадают параметры вне таблицы эмбеддингов.

Новые запуски выполняются по восемь параллельно, каждый закреплён за одним
физическим ядром. Их время не сопоставляется с последовательными замерами
пилота. Порядок заранее перемешан с seed 20261024. Скрипт сохраняет результат
каждого завершённого запуска и допускает продолжение без повторения готовых
запусков; SHA-256 каждого лога записан в отдельный файл завершения.

Для каждого варианта рассчитаны среднее, выборочное стандартное отклонение,
медиана и 95% доверительный интервал среднего: `mean ± t(0.975, n−1) × sd/√n`.
Для сравнения двух вариантов сначала вычисляется разница loss на каждом
одинаковом seed, затем средняя разница и её интервал. Это
[парное сравнение по методике NIST](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm).
Наличие нуля в интервале не доказывает эквивалентность вариантов.

Для всех 28 пар восьми вариантов рассчитаны двусторонние парные t-тесты
с поправкой Holm. Семейство из 28 сравнений рассматривается отдельно
для dev и test. Обычные 95% интервалы в таблицах не скорректированы на
множественные сравнения; при утверждении статистической значимости
используется скорректированное p < 0.05. Дополнительно сохранены парные
процентильные bootstrap-интервалы по 20 000 перевыборок seed.

Сводки рассчитаны и для всех 20 seed, и отдельно для 17 новых seed:
это позволяет проверить, сохраняется ли вывод после пилотного выбора
лидера. Доверительные интервалы описывают разброс инициализации на одном
фиксированном split; они не измеряют неопределённость от выбора других
имён или другого разделения данных. Test использовался в нескольких
исследовательских сравнениях, поэтому это не новая независимая тестовая выборка.

### Уменьшение модели и обучения для фиксированного куба ±1 + SiLU

Базовая конфигурация: три предыдущих символа, embedding=8, первый слой=64,
batch=32, 200 000 шагов, learning rate 0.1 до шага 100 000 и 0.01 после.
Эмбеддинги фиксированы, полуширина куба равна 1. Варианты используют ту же
формулу выбора вершин по номеру; при embedding=4 для 27 символов получается
решётка с тремя уровнями на ось, а не только двоичные вершины ±1. Поэтому
уменьшение embedding меняет и размер, и геометрию представления.

До опытов выбран практический предел «схожего качества»: ухудшение NLL
не более 0.005, примерно 0.5% perplexity. Отбор выполняется только по dev
на пяти seed 42–46. Для подтверждения выбраны новые seed 62–81, которых
не было в предыдущем сравнении активаций. Основная модель урока не меняется;
экспериментальные настройки находятся в `benchmarks/frozen_embeddings/cube_reductions`.

Проверяются размер эмбеддинга, размер первого слоя, число предыдущих
символов, batch, число шагов, момент изменения learning rate и меньшие
learning rate. После первого грубого поиска проверяются более осторожные
сокращения и сочетания изменений. Финальные конфигурации фиксируются
в `selection.json` до запуска подтверждающей серии.

Из оставшихся констант `RANDOM_SEED` не имеет «меньшего» вычислительного
размера: он задаёт случайную последовательность. Доли train/dev и `NAMES_TEXT`
сохранены, чтобы сравнение использовало одни данные. `GENERATED_NAMES_COUNT`
и `MAX_GENERATED_NAME_LENGTH` ограничивают демонстрационную генерацию после
обучения и не уменьшают число параметров или training loss. `ZERO_F32` —
математический ноль, не настраиваемый ресурс. `USE_REGULAR_CUBE_EMBEDDINGS`
и `REGULAR_CUBE_HALF_WIDTH_SQUARED` в этом опыте уже true и 1.0; это именно
фиксированный куб с SiLU, а не исходный режим основного файла.

Количество хранимых коэффициентов при словаре из 27 символов:
`27E + (P×E + 1 + 27)H + 27`, где E — embedding, P — число предыдущих
символов, H — размер первого слоя. Из них 27E — фиксированные эмбеддинги,
остальные обучаются. Память коэффициентов — четыре байта на число f32;
это не полная память процесса: градиенты, промежуточные массивы и данные
нужно учитывать отдельно. Уменьшение batch или шагов не уменьшает таблицы
весов. Batch уменьшает объём работы на шаг и размер батча промежуточных
результатов; сокращение шагов уменьшает число обновлений.

Запуски выполняются на восьми физических ядрах параллельно. Время в таблицах
— ориентир для этой нагрузки, а не последовательный микробенчмарк. Все
варианты одного размера начинаются с побитно одинаковых параметров при
одном seed. При изменении размеров формы и последовательность потребления
случайных чисел меняются; сравниваются одинаковые seed, но не одинаковые
матрицы разного размера. Контрольные базовые запуски должны точно
воспроизвести предыдущие train/dev/test loss на совпадающих seed.

- **125 000 шагов, переключение на 100 000**: на 37.5% меньше шагов,
  test NLL вырос всего на 0.00173 (около 0.17% perplexity). Это более
  осторожный компромисс, когда близость loss важнее максимального ускорения.
- **Первый слой 62 вместо 64 при прежних 200 000 шагах**: 3467 вместо
  3571 коэффициента, экономия 2.9%. Таблицы коэффициентов занимают 13 868
  вместо 14 284 байт: выигрыш только 416 байт. Среднее ухудшение test — 0.00098.
- **Batch 24 и 150 000 шагов**: примерно на 43.75% меньше обработанных
  обучающих примеров и на 25% меньше элементов в полном батче промежуточных
  результатов. Число коэффициентов прежнее. Вариант прошёл критерий,
  но запас меньше: верхняя 95% граница ухудшения test 0.00485.

Это отдельные проверенные конфигурации. Результат слоя 62 при 200 000 шагах
не гарантирует тот же результат при одновременном сокращении до 110 000
или 125 000: такого сочетания в подтверждающей серии нет. Сильные сокращения
embedding и первого слоя в отборе заметно ухудшали dev NLL. Поэтому основная
подтверждённая экономия здесь — обучение, а не размер таблиц модели.

## Исторический эксперимент: упрощённые формулы в BF16 mixed

Проведены 40 полных обучений (8 вариантов × 5 seed, 125 000 шагов) и отдельные 40 последовательных замеров скорости по 10 000 шагов. На Ryzen 7 9800X3D Hard-Swish без расчёта ln на обучающих шагах дал test NLL 2.202980 против 2.204584 у SiLU и ускорение около 1.05×. Разница качества статистически неубедительна на пяти seed. ReLU и Leaky ReLU проще и быстрее примерно в 1.18× и 1.16×, но средний test NLL немного хуже — 2.209007 и 2.208941.

Удаление ln на обучающих шагах не изменило итоговые веса или метрики ни в одной из 15 пар, но устойчивого ускорения не показало. Экспериментальная замена softmax рациональной нормализацией убирает exp из обучающего прохода полностью, однако дала test NLL 2.290230 при ускорении лишь около 1.16×. Основной код урока по результатам этого сравнения не изменён.

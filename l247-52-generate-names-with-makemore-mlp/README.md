## 1. Словарь и задача предсказания

В `data/names.txt` 32 033 имени. Буквы a–z получают индексы 1–26, точка — 0. Точка означает и пустой начальный контекст, и конец имени. Для `emma` получаются:

| Контекст X | Цель Y |
|---|---|
| `...` | `e` |
| `..e` | `m` |
| `.em` | `m` |
| `emm` | `a` |
| `mma` | `.` |

Каждая строка X — три целых индекса, Y — один индекс. Всего 228 146 примеров. Контекст сбрасывается между именами: последнее имя не подсказывает начало следующего. Сначала перемешиваем **имена** с seed 42, выделяем 80% train, 10% dev и 10% test, и только затем строим примеры. Иначе контексты одного имени могли бы попасть одновременно в обучение и оценку.

## 2. Lookup вместо one-hot

Начальная демонстрация использует `C: (27,2)`. Строка `C[i]` — обучаемые координаты буквы i. Умножение one-hot вектора длины 27 на C даёт ровно ту же строку, но прямой lookup не тратит вычисления на нули. `C[X]` для мини-батча даёт `(B,3,2)`. Объединяем координаты трёх букв в `(B,6)`; порядок букв сохраняется. Первый слой имеет веса `(6,100)`, смещение `(100)`, затем `tanh`, выходной слой `(100,27)` и смещение `(27)`.

`main` печатает формы, пример прямого прохода, сумму вероятностей и сравнение явного `exp → нормализация → -log(p_target)` со стабильной cross-entropy. Для демонстрации loss первых 32 целей берутся именно первые 32 контекста. В сохранённом notebook ячейка 19 использует `arange(32)` с полным Y, поэтому её нельзя буквально запускать после всех предыдущих ячеек без исправления размеров.

## 3. Полная модель

| Тензор | Форма | Параметров |
|---|---|---:|
| C | 27 × 10 | 270 |
| W1 | 30 × 200 | 6000 |
| b1 | 200 | 200 |
| W2 | 200 × 27 | 5400 |
| b2 | 27 | 27 |
| Всего | | **11 897** |

Прямой проход: `emb = C[X]`, `x = flatten(emb)`, `h = tanh(x W1 + b1)`, `logits = h W2 + b2`. Для B=32 формы: `(32,3,10) → (32,30) → (32,200) → (32,27)`. Смещения прибавляются к каждой строке. `tanh` нужен для нелинейности; два линейных слоя без него можно свернуть в один.

Все пять тензоров инициализируются независимыми стандартными нормальными числами с seed 2147483647, как по смыслу в notebook. Большие начальные logits дают большую начальную ошибку; здесь намеренно сохранена исходная инициализация, без добавления BatchNorm или Adam.

Cross-entropy для одного примера:

```text
m = max(logits)
loss = m - logits[target] + ln(sum(exp(logits - m)))
```

Это та же `-ln(probability_of_correct_character)`, но без переполнения `exp` и без `ln(0)`. Loss усредняется по примерам; случайное равномерное предсказание даёт `ln(27) ≈ 3.296`.

## 4. Обратный проход и SGD

Весь код урока находится внутри `main` в `src/main.rs`: численные функции и структуры локальны для неё, проверяемые типы также объявлены непосредственно внутри `main`. Открой метод `gradients`. Вместо `loss.backward()` здесь явно записано правило цепочки:

```text
dlogits = (softmax(logits) - one_hot(Y)) / B
dW2 = hᵀ dlogits                  db2 = sum_rows(dlogits)
dh = dlogits W2ᵀ
da = dh * (1 - h²)
dW1 = xᵀ da                       db1 = sum_rows(da)
dx = da W1ᵀ
dC[буква] += соответствующие координаты dx
```

Последний `+=` принципиален: одна буква может встретиться несколько раз внутри контекста и в разных примерах мини-батча. Все вклады должны сложиться. На каждом шаге выделяются нулевые градиенты. Все производные используют старые W1/W2, после чего `step` обновляет все параметры: `p -= lr * grad`.

Мини-батч содержит 32 случайных примера с возвращением. Выполняются 200 000 шагов: `lr=0.1` на шагах 0…99 999 и `lr=0.01` на остальных. Переменная `training_steps` сокращает или продлевает число шагов, но не переносит границу смены lr. Это число обновлений, а не эпох.

## 5. Качество, графики и генерация

После обучения считаем среднюю cross-entropy по **всему** train и dev без изменения параметров. По dev можно выбирать размер модели и скорость обучения. Test используется только для итоговой оценки: в notebook он подготовлен, но не оценён; здесь метрика дополнительно выводится. Не подбирай настройки по test.

Кривая `log10(loss)` шумит, поскольку каждый мини-батч другой; уменьшение lr обычно уменьшает шум. `embeddings.svg` показывает только координаты 0 и 1 десятимерного C — это не PCA и не полное расстояние между буквами. Близость на этой картинке может указывать на похожее использование букв, но не доказывает его во всех десяти измерениях.

Генерация начинает с `...`. Сеть выдаёт распределение вероятностей следующего символа, из него случайно выбирается индекс, контекст сдвигается, и процесс повторяется до точки. Это sampling, а не argmax: можно получить разные имена. Генератор для sampling имеет отдельный seed 2147483657. Ограничение 100 символов защищает от бесконечного вывода плохо обученной модели; усечённый результат явно помечается.

## Как читать имена в коде

В коде используются полные имена; короткие C, W1, b1, W2, b2 остаются в формулах для сверки с notebook.

| Имя в Rust | Значение |
|---|---|
| `vocabulary` / `vocabulary_size` | Словарь символов / число символов в нём |
| `context_character_indices` | Индексы трёх предыдущих букв |
| `target_character_index` | Индекс следующей буквы, которую нужно предсказать |
| `embedding_dimensions` | Число обучаемых координат одной буквы |
| `hidden_neuron_count` | Число нейронов скрытого слоя |
| `character_embeddings` | Таблица координат букв, C |
| `flattened_embeddings` | Координаты трёх букв, объединённые в один вектор |
| `input_to_hidden_weights`, `hidden_biases` | W1 и b1: веса и смещения скрытого слоя |
| `hidden_activations` | Выходы скрытых нейронов после tanh |
| `hidden_to_output_weights`, `output_biases` | W2 и b2: веса и смещения выходного слоя |
| `character_scores` | Logits: оценки букв до преобразования в вероятности |
| `character_probabilities` | Вероятности букв после softmax |
| `training_examples`, `validation_examples`, `test_examples` | Примеры для обучения, выбора настроек и окончательной оценки |
| `training_batch` | Мини-батч: группа примеров для одного обновления весов |
| `learning_rate` | Скорость обучения: множитель при вычитании градиента |
| `score_gradients` | Производные ошибки по выходным оценкам букв |
| `hidden_pre_activation_gradients` | Производные ошибки по суммам скрытого слоя до tanh |
| `input_to_hidden_weight_gradients` | Производные ошибки по весам W1 |
| `input_coordinate_gradient` | Производная ошибки по одной координате входного вектора |

Суффикс `_index` обозначает позицию, `_count` — количество, `_gradients` — производные ошибки по соответствующим значениям. `parameters` хранит пять тензоров в порядке C, W1, b1, W2, b2; при вычислениях они получают отдельные смысловые имена через распаковку массива.

## Проверка входных данных через типы

Вместо входных `assert!` используются локальные типы с проверяемым созданием через `TryFrom`:

- `TrainingSteps::try_from(число)` принимает только положительное число шагов.
- `Names::try_from(текст)` принимает непустой список непустых имён из a–z. Локальный блок перемешивания меняет только порядок и сохраняет проверенный тип.
- `NonEmptySlice::try_from(срез)` проверяет непустой набор примеров без копирования данных. `Model::loss` и локальный расчёт градиентов используют именно этот тип.

Ошибки возвращаются строками `&'static str` и передаются вызывающему коду через `?`. После создания типа проверки не повторяются внутри численных методов. Изменяемого доступа к внутреннему срезу нет.

# 244 · MNIST: Линейный классификатор и softmax

[Пошаговый пример с JSON: от пикселей до обновления весов](EXAMPLE_JSON.md).

Изучи отличие от урока 243: вместо одного среднего изображения на класс обучаются коэффициенты влияния каждого пикселя на десять оценок класса. Архитектура: 784 → 10, всего 7 850 параметров (784×10 весов и 10 смещений).

Для класса c: `score[c] = sum(pixel[j] * W[j,c]) + b[c]`. Softmax превращает scores в вероятности; loss — отрицательный логарифм вероятности правильной цифры. Градиент `(p - one_hot)/batch` проходит через линейный слой; Adam обновляет веса и смещения. Последовательность вычислений видна в функции `main` файла `src/main.rs`, цикл обучения находится в этом же файле.

Это линейная граница между классами: модель уже использует больше информации, чем средние изображения, но не строит нелинейные сочетания штрихов.

## Запуск

Из папки урока:

```bash
python3 ../scripts/prepare_mnist.py
cargo run
```

Настройки внутри `main` (размер группы — в шаге 1, параметры обучения — в шаге 7): 15 эпох, batch-size 64, learning-rate 0.001, seed 42, полный train. Обучение идёт на CPU. Обычный `cargo run` использует оптимизацию, настроенную в корневом Cargo.toml.

[Правила эксперимента и сравнение моделей](../MNIST.md) описывают загрузку PNG, разделение данных, Adam и параметры обучения. Метка берётся из имени папки, 784 пикселя нормализуются делением на 255. Каждый пятый PNG каждого класса используется для validation; test не участвует в обучении и выборе эпохи.

Вывод содержит train loss, validation loss и accuracy по эпохам, выбранную по validation loss эпоху, итоговый test и матрицу ошибок. Результат не гарантирован одной архитектурой: важны данные, скорость обучения и число эпох.

## Самостоятельное задание

1. Для scores [0,0] и правильного класса 0 вручную вычисли вероятности, loss и градиент по scores для batch=1.
2. Объясни, почему softmax не меняет класс, выбранный по максимальному score, но нужен для loss.
3. Запусти обучение, сравни с уроком 243 на одинаковом test. Запиши seed, размеры частей, выбранную эпоху и метрики.
4. На validation сравни две скорости обучения; объясни, почему нельзя выбирать скорость по test.
5. Найди в матрице ошибок наиболее частую ошибку и открой соответствующие PNG в тестовой папке.

Урок пройден, если можешь объяснить прямой и обратный проход модели, какие параметры обучаются, почему выбор эпохи идёт по validation и как проверить метрику на настоящих PNG.

Проверенный полный запуск с настройками по умолчанию: **92,72% accuracy на test**. [Сравнение и журналы запусков](../MNIST.md#проверенный-запуск-на-полном-mnist).

Формулы модели, параметры, обучение и оценка находятся внутри `main`. Закрытые числовые типы и их проверки вынесены в общий модуль `mnist_data::numeric_types`. Загрузчик PNG и тип `Digit` импортируются из [mnist_data](../mnist-data/src/lib.rs). Для повторяющихся операций используются локальные замыкания. Путь к данным и настройки заданы в коде. Запуск без аргументов загружает MNIST, обучает модель и выводит метрики.

## Как читать код по шагам

В `src/main.rs` шаги отмечены комментариями. Шаг 3 один раз преобразует загруженные яркости. Замыкания шагов 4–6 задают операции, вызываемые во время обучения и оценки.

1. **Данные.** `load_mnist_images` возвращает train, validation и test. Одна запись содержит `[NormalizedPixelBrightnessFiniteFrom0To1InclusiveF64; 784]` и правильную цифру. Диапазон яркостей проверяется общим загрузчиком.
2. **Устройство модели.** Модель — массив `pixel_weights_and_biases_by_digit: [PixelWeightAndBias; 10]`. Для каждой цифры `pixel_weights[пиксель]` имеет тип `[PixelWeightFiniteF32; 784]` и хранит её 784 веса, а `bias` — одно смещение. `ImagePixelsWithActualDigitAndScoresByDigit` хранит одну картинку (`pixels: [PixelBrightnessForComputationFiniteFrom0To1InclusiveF32; 784]`) её правильную цифру (`actual_digit: Digit`) и десять оценок (`scores_by_digit: [DigitScoreFiniteF32; 10]`). Результаты группы представлены `Vec<ImagePixelsWithActualDigitAndScoresByDigit>`.
3. **Группа картинок.** `convert_image_pixel_brightness_from_f64_to_f32` принимает ссылки на выбранные записи, проверяет яркости через `TryFrom`, переводит их в `f32` и возвращает `Vec<([PixelBrightnessForComputationFiniteFrom0To1InclusiveF32; 784], Digit)>`, сохраняя картинку и правильную цифру вместе.
4. **Прямой проход.** `build_images_pixels_with_actual_digits_and_scores_by_digit` складывает произведения пикселей на веса и прибавляет смещения. Получаются десять оценок на картинку.
5. **Ошибка и производные.** `calculate_mean_loss_and_score_gradients_by_digit` выполняет softmax, считает среднюю cross-entropy и производные по оценкам. Правильная цифра нужна именно здесь.
6. **Проверка качества.** `measure_prediction_quality` использует операции шагов 3–5, выбирает максимальную оценку каждой картинки и считает точность. Веса не обновляются.
7. **Подготовка обучения.** Создаются порядок картинок, случайные начальные веса и нулевая память Adam. Seed задаёт воспроизводимую последовательность случайных чисел.
8. **Начальная проверка.** Измеряется качество ещё не обученной модели на validation — эпоха 0.
9. **Обучение.** На каждой эпохе ссылки на обучающие записи перемешиваются. Для каждой группы последовательно выполняются шаги 9.1–9.5: сборка группы → оценки → ошибка и производные оценок → производные параметров → обновление Adam. Изменение весов и смещений и есть обучение.
10. **Выбор модели.** После каждой эпохи измеряется validation loss. Если она уменьшилась, сохраняется копия текущей модели. Затем начинается следующая эпоха.
11. **Итоговый test.** Выбранная копия проверяется один раз; выводятся ошибка, точность и таблица предсказаний. Например, элемент `[7][1]` считает семёрки, принятые за единицы.

Операции модели и обучение остаются внутри `main`. Временные значения ограничены своим этапом. Общие загрузчик и `Digit` находятся в `mnist_data`.

Фиксированные размеры закреплены массивами: 784 пикселя и веса, 10 оценок и их градиентов, 10 счётчиков для каждой истинной цифры в итоговой таблице. `Vec` хранит переменное число картинок, меток, ссылок и предсказаний; последний batch может быть неполным.

Яркости train, validation и test преобразуются в `f32` один раз на шаге 3. Эпохи и проверки используют ссылки на готовые записи. Модель, градиенты и память Adam используют разные типы: вес нельзя случайно подставить вместо градиента. Оценки вычисляются заново для текущих весов.

## Числовые типы

| Тип | Значение и допустимый диапазон |
| --- | --- |
| `NormalizedPixelBrightnessFiniteFrom0To1InclusiveF64` | Конечная яркость `f64` от 0 до 1; проверяется до округления. |
| `PixelBrightnessForComputationFiniteFrom0To1InclusiveF32` | Проверенная яркость `f32` от 0 до 1. |
| `PixelWeightFiniteF32` | Конечный вес любого знака. |
| `BiasFiniteF32` | Конечное смещение любого знака. |
| `DigitScoreFiniteF32` | Конечная оценка цифры любого знака, до softmax. |
| `ProbabilityFiniteFrom0To1InclusiveF32` | Конечная вероятность от 0 до 1. |
| `GradientFiniteF32` | Конечная производная ошибки любого знака. |
| `NonNegativeFiniteF32` | Конечная экспонента или среднее квадратов, не меньше нуля. |

Поля обёрток закрыты. `TryFrom` проверяет допустимость, `value()` возвращает копию числа для формулы. Результаты формул снова проверяются при создании типа; ошибки передаются через `Result`. `ProbabilityFiniteFrom0To1InclusiveF32` проверяет отдельное число, а сумма вероятностей получается нормировкой softmax. Пиксели остаются типизированными после преобразования и не смешиваются с весами или оценками. Например, яркость 0.8 при весе −2 и смещении 0.5 даёт допустимую отрицательную оценку −1.1.

`PixelWeightAndBiasGradients` хранит производные весов и смещения. `AdamMoments` содержит средний `GradientFiniteF32` и неотрицательное среднее квадратов; `PixelWeightAndBiasAdamMoments` хранит эти моменты для параметров одной цифры. Промежуточные суммы и статистика ошибки используют `f32`.

# 244 · MNIST: Линейный классификатор и softmax

Изучи отличие от урока 243: вместо одного среднего изображения на класс обучаются коэффициенты влияния каждого пикселя на десять оценок класса. Архитектура: 784 → 10, всего 7 850 параметров (784×10 весов и 10 смещений).

Для класса c: `score[c] = sum(pixel[j] * W[j,c]) + b[c]`. Softmax превращает scores в вероятности; loss — отрицательный логарифм вероятности правильной цифры. Градиент `(p - one_hot)/batch` проходит через линейный слой; Adam обновляет веса и смещения. Последовательность вычислений видна в функции `main` файла `src/main.rs`, цикл обучения находится в этом же файле.

Это линейная граница между классами: модель уже использует больше информации, чем средние изображения, но не строит нелинейные сочетания штрихов.

## Запуск

Из папки урока:

```bash
python3 ../scripts/prepare_mnist.py
cargo run
```

Настройки в начале `main`: 15 эпох, batch-size 64, learning-rate 0.001, seed 42, полный train. Обучение идёт на CPU. Обычный `cargo run` использует оптимизацию, настроенную в корневом Cargo.toml.

[Правила эксперимента и сравнение моделей](../MNIST.md) описывают загрузку PNG, разделение данных, Adam и параметры обучения. Метка берётся из имени папки, 784 пикселя нормализуются делением на 255. Каждый пятый PNG каждого класса используется для validation; test не участвует в обучении и выборе эпохи.

Вывод содержит train loss, validation loss и accuracy по эпохам, выбранную по validation loss эпоху, итоговый test и матрицу ошибок. Результат не гарантирован одной архитектурой: важны данные, скорость обучения и число эпох.

## Самостоятельное задание

1. Для scores [0,0] и правильного класса 0 вручную вычисли вероятности, loss и градиент по scores для batch=1.
2. Объясни, почему softmax не меняет класс, выбранный по максимальному score, но нужен для loss.
3. Запусти обучение, сравни с уроком 243 на одинаковом test. Запиши seed, размеры частей, выбранную эпоху и метрики.
4. На validation сравни две скорости обучения; объясни, почему нельзя выбирать скорость по test.
5. Найди в матрице ошибок наиболее частую ошибку и открой соответствующие PNG в тестовой папке.

Урок пройден, если можешь объяснить прямой и обратный проход модели, какие параметры обучаются, почему выбор эпохи идёт по validation и как проверить метрику на настоящих PNG.

Проверенный полный запуск с настройками по умолчанию: **92,72% accuracy на test**. [Сравнение и журналы запусков](../MNIST.md#проверенный-запуск-на-полном-mnist).

В уроке объявлена только функция `main`: числовые операции, параметры, обучение и оценка находятся внутри неё. Загрузчик PNG и тип `Digit` импортируются из [mnist_data](../mnist-data/src/lib.rs). Для повторяющихся операций используются локальные замыкания. Путь к данным и настройки заданы в коде. Запуск без аргументов загружает MNIST, обучает модель и выводит метрики.

Код оформлен как в уроке 243: PNG читает `load_labeled_png_images`, затем явно готовятся `train_images`, `validation_images` и `test_images`. У `LinearLayer` именованные поля `weights` и `biases`; `ForwardPass` хранит входы и оценки цифр. Каждая проверенная картинка представлена `DigitPrediction { actual_digit, predicted_digit }`, а `PredictionEvaluation` содержит `mean_loss`, `accuracy` и список предсказаний.

`measure_prediction_quality` принимает текущие веса: они меняются после каждой эпохи. Итоговое `evaluate_digit_predictions` использует выбранную модель из окружающего `main` и сразу печатает результаты. Формулы softmax, cross-entropy и Adam, начальные настройки и порядок перемешивания сохранены. Объявления модели и операций обучения остаются внутри `main`; загрузчик и `Digit` находятся в `mnist_data`.

# Как читать названия функций

В уроках имя функции сначала объясняет, **что получаем**, затем — **как это вычисляем**. Используем форму `calc_<результат>_by_<действия>` или `calc_<результат>_as_<формула>`. В имени оставляем только вычисляемый результат и реально выполняемые действия. Пояснения о знаке, границах, геометрическом смысле и назначении результата пишем в комментариях, а не в суффиксах имени. Это правило относится также к переменным, параметрам, полям структур и названиям уроков. Перед определением простыми словами объясняем действия с числами и смысл результата. Термин, если он нужен, приводим только после объяснения.

Например, `multiply_matching_coords_then_add_results` умножает числа на одинаковых местах и складывает результаты; угол между векторами она не вычисляет. Поэтому пояснение про угол находится только в комментарии. Функция `multiply_matching_coords_then_add_results_and_normalize_by_both_vec_lens` дополнительно делит сумму на произведение длин.

Например, `calc_vec_len_as_square_root_of_sum_of_squared_coords` читается как «вычислить длину вектора как квадратный корень из суммы квадратов координат». Для `[3, 4]` это `sqrt(3² + 4²) = 5`. Математический термин — **евклидова норма**, или **длина вектора**.

- Для короткой формулы указываем результат и операции: например, длина вектора — корень из суммы квадратов, среднее — сумма, делённая на количество.
- Для большого алгоритма указываем вычисляемый результат и основные действия: например, вычисление контекста через взвешенное сложение значений.
- Функции `plot_...` строят графики; имя связывает показанную величину со способом её вычисления, когда это помогает понять результат.
- `main` остаётся стандартной точкой входа Rust. Имена, которые уже объясняют результат и действие, например `generate_random_number_between_zero_and_one`, сохраняются.

Названия уроков, пакетов и каталогов тоже связывают результат со способом его получения. Например: «Длина вектора: квадратный корень из суммы квадратов координат». Эти названия согласованы с планом курса. Каталоги и имена пакетов Cargo начинаются с `l001-01-`; Cargo не допускает цифру в начале имени. Принятые математические термины сохранены в пояснениях к коду. В уроках без отдельных вычислительных функций операции находятся непосредственно в `main`. Имя каталога и пакета имеет вид `lNNN-BB-<основная-функция>`: имя основной функции переносится целиком, а `_` заменяется на `-`. Если библиотека содержит несколько операций, название задаёт основная операция урока (например, обучение токенизатора), остальные показаны в том же уроке. Для уроков с вычислениями непосредственно в `main` название описывает задание и использует те же сокращения: `calc`, `vec`, `coords`, `coord`, `diffs`, `diff`, `dist`, `pos`, `neg`, `len`.

Следующие пояснения относятся к комментариям и не включаются в имена функций или уроков:

- Косинусное сходство: `1` — одно направление, `0` — перпендикулярность, `−1` — противоположные направления. Нулевой вектор возвращает ошибку.
- Скалярное произведение — ненормированное совпадение направлений: для ненулевых векторов положительный знак означает угол меньше 90° (включая 0°), отрицательный — больше 90° (включая 180°), но величина зависит и от длин. Ноль также возможен для нулевого вектора.
- При построении единичного вектора `cos` — горизонтальная координата, `sin` — вертикальная. При повороте пары координат `cos` задаёт вклад прежней оси, `sin` — вклад другой оси. Это разные роли одной тригонометрии.
- `tanh` — гиперболический тангенс: сохраняет знак, при нуле даёт ноль, при больших по модулю входах приближается к `−1` или `1`. Обычных `tan` и `cot` в текущих уроках нет; при добавлении поясняем их конкретную роль и область определения.
- Сигмоида переводит нулевой вход в `0.5`. Её результат означает вероятность класса либо долю пропускаемого сигнала. Управляющая доля `0` блокирует сигнал, `1` пропускает его полностью; конечный вход математически даёт внутреннее значение между ними. У SiLU множитель может быть отрицательным или больше единицы.
- Accuracy: `1` — все прогнозы верны, `0` — все неверны. Precision: `1` — нет ложных тревог. Recall: `1` — ни один положительный пример не пропущен. F1: `1` — нет ни ложных тревог, ни пропусков; текущая реализация возвращает `None` при неопределённых долях или их нулевой сумме.
- ROC-AUC: `1` — правильный порядок всех положительно-отрицательных пар, `0` — обратный; `0.5` — отсутствие преимущества по попарному ранжированию. Энтропия двух классов в битах: `0` — один класс, `1` — равные доли; для бинарной меры Джини максимум равен `0.5`.
- Средние абсолютная и квадратичная ошибки: `0` — точные прогнозы, больше — хуже. Для отрицательного логарифма вероятности правильного ответа меньше — лучше; perplexity интерпретируется как эффективное число вариантов, минимум `1`.
- Дисперсия: `0` — одинаковые значения, больше — сильнее разброс. Знак ковариации показывает направление совместного линейного изменения; нулевая ковариация не доказывает независимость.
- Производная — локальное изменение выхода на единицу изменения входа. Положительный градиент ошибки требует уменьшать параметр при градиентном спуске, отрицательный — увеличивать. Нулевой градиент сам по себе не гарантирует минимум.
- Доля сохраняемой памяти: `0` — забыть старое, `1` — сохранить всё. Доля исходного сигнала в диффузии: `0` — только шум, `1` — исходный сигнал. Доля объяснённого разброса: `0` — ничего не сохранено, `1` — сохранён весь разброс.

Удлиняем имя ради интерпретации, а не добавляем одинаковую шкалу всем величинам. Счётчики, индексы и операции с уже ясным назначением сохраняют обычные описательные имена. Подписи графиков остаются короткими, а длинные поясняющие имена используются в коде.

## Приблизительное равенство дробных чисел

В уроках используются обёртки из [lesson-float-comparison](lesson-float-comparison/src/lib.rs): допуск указан в имени, поэтому передаются только два сравниваемых числа.

```rust
use lesson_float_comparison::check_f64_eq_1e_minus_10;

assert!(check_f64_eq_1e_minus_10(actual, expected));
```

Доступны функции `check_f64_eq_1e_minus_2`, `check_f64_eq_1e_minus_6`, `check_f64_eq_1e_minus_7`, `check_f64_eq_1e_minus_8`, `check_f64_eq_1e_minus_9`, `check_f64_eq_1e_minus_10` и `check_f64_eq_1e_minus_12`. Например, `1e-2` — это `0.01`, `1e-6` — `0.000001`, `1e-12` — `0.000000000001`. Чем меньше допуск, тем строже сравнение. Все обёртки вызывают общую функцию `compare_2_floats_for_approximate_equality(first, second, absolute_tolerance)`, которую можно использовать для другого допуска.

Разница должна быть строго меньше допуска: на границе проверка возвращает `false`. `NaN` и бесконечности также не считаются приблизительно равными. Это абсолютный допуск, не зависящий от величины чисел. Проверка близости к нулю использует вторым аргументом `0.0`. Прежние допуски уроков сохранены.

Сравнение двух величин ошибки («эта ошибка меньше другой»), проверка диапазона и проверка допустимой ошибки квантования сохраняют свой математический смысл и не заменяются приблизительным равенством.

## Как писать пояснения к урокам

Сначала объясняем, что берём на входе, что делаем и зачем нужен результат. Предпочитаем знакомые слова и маленький числовой пример, даже если текст получается длиннее. Например: «умножаем числа на одинаковых местах и складываем результаты» вместо необъяснённого «скалярное произведение»; «меняем строки таблицы на столбцы» вместо одного слова «транспонирование».

Не объясняем неизвестное слово через несколько других неизвестных слов. Если термин понадобится дальше, сначала раскрываем смысл и только затем называем термин. Указываем ограничения и смысл значений: например, почему нельзя делить на ноль или что означает результат 0. Названия функций сами по себе не заменяют понятного пояснения. Избегаем отдельных строк с перечнем терминов без объяснения.

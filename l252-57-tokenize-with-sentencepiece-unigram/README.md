# 252 · SentencePiece: куски, вероятности и выбор всего разбиения

Продолжение [урока 251 о tiktoken](../l251-56-tokenize-by-byte-pair-merges/README.md). Здесь тоже в конце получается список чисел. `enumerate` по-прежнему может назначить ID записям словаря. Сложность до этого: какие куски включить в словарь и какие из них выбрать для конкретного текста?

SentencePiece — библиотека, которая поддерживает несколько моделей, в том числе **BPE и Unigram**. Поэтому противопоставлять «BPE или SentencePiece» неверно. Этот урок разбирает Unigram: готовый словарь хранит куски с оценками, а кодировщик ищет лучшее полное разбиение.

## Запуск

```bash
cargo run -p l252-57-tokenize-with-sentencepiece-unigram
cargo test -p l252-57-tokenize-with-sentencepiece-unigram
```

Пример целиком на Rust. `sentencepiece-rs` — сторонняя реализация runtime SentencePiece на Rust, не официальный C++ binding. Он загружает настоящий включённый `data/toy.model`. Python, C++ и интернет при запуске собранного примера не нужны. При первой сборке Cargo скачивает зависимости.

## 1. Пробел тоже нужно представить

SentencePiece может обучаться на исходных предложениях без внешнего разбиения на слова. Внутренняя подготовка зависит от настроек модели. В нашей модели пробел отображается знаком `▁` (U+2581), а к началу непустого текста добавляется условный пробел: `banana` → `▁banana`. Поэтому `▁banana` в словаре может быть одним токеном. Это не специальный BOS-токен: `<s>` — отдельная запись с другим назначением.

Наша модель использует `nmt_nfkc`: нормализует совместимые Unicode-формы и лишние пробелы. Запуск показывает, что `  banana   banana  ` восстанавливается как `banana banana`, а полноширинное `ＢＡＮＡＮＡ` нормализуется в `BANANA` (этих заглавных букв нет в нашем корпусе, поэтому далее получается `<unk>`). Декодирование возвращает нормализованный текст; исходное форматирование не обязано сохраняться.

## 2. Почему выбирается такое разбиение

Начало main использует маленький вручную заданный словарь. ID — индекс строки; вероятность p — отдельное число:

| ID | Кусок | p |
|---|---|---|
| 0 | ▁ | 0.10 |
| 1 | a | 0.35 |
| 2 | b | 0.35 |
| 3 | ab | 0.05 |
| 4 | ▁ab | 0.15 |

Для `▁ab` доступны три пути:

- `▁ab`: вероятность 0.15.
- `▁` + `ab`: 0.10 × 0.05 = 0.005.
- `▁` + `a` + `b`: 0.10 × 0.35 × 0.35 = 0.01225.

Побеждает первый. Но если задать p(`a`)=p(`b`)=0.44, p(`ab`)=p(`▁ab`)=0.01, p(`▁`)=0.10, то три коротких куска дадут 0.01936 и победят длинный с p=0.01. Это запускается во втором примере. Наличие целого слова в словаре не гарантирует его выбор.

Чтобы не перемножать много маленьких чисел, складываем ln(p). Максимум произведения и максимум суммы логарифмов дают один путь. Отрицательная оценка не означает отрицательную вероятность.

`segment` реализует динамическое программирование (Viterbi). В позиции 0 оценка 0. Из каждой достижимой позиции пробуем все совпадающие куски и улучшаем оценку в позиции конца куска. Сохраняем лучший путь к каждой позиции. Идём до конца строки; если покрытия нет — возвращаем `None`. Перебираем только границы UTF-8 символов. Программа печатает переходы и суммы оценок; это компактная учебная реализация, без нормализатора, `<unk>`, sampling и ускоряющих структур production runtime.

## 3. Откуда берутся куски и оценки при обучении

Вручную мы задали их для прозрачного вычисления. Настоящий Unigram trainer создаёт большой набор кандидатов из корпуса, оценивает вероятности разбиений, обновляет оценки по ожидаемым использованиям кусков (EM), затем постепенно удаляет кандидатов с малым вкладом до нужного размера словаря, сохраняя необходимое покрытие. Он учитывает альтернативные разбиения при обучении; это шире, чем просто пересчитать токены одного лучшего пути. При обычном детерминированном кодировании готовой моделью выбирается лучший путь; возможно и семплирование альтернатив, которое этот урок не включает.

В `toy.vocab` можно посмотреть сохранённые куски и оценки. Номер строки соответствует ID; у обычных Unigram-кусков оценка используется как логарифмический вес. Служебные записи обрабатываются отдельно. `toy.model` содержит также тип модели и настройки нормализации. Перенумерация строк без согласования с нейросетью изменит смысл входных чисел.

## 4. Настоящая модель в Rust

Вторая половина main показывает нормализацию, куски, ID и decode для латиницы, русского текста, пробелов, полноширинных букв, emoji и пустой строки. Наша маленькая модель обучена только на семи строках `data/corpus.txt`; это демонстрационные данные, написанные для урока. Размер запрошен 64, но `hard_vocab_limit=false` разрешает меньший словарь.

`byte_fallback` здесь выключен. Неизвестный emoji получает ID `<unk>` и не восстанавливается точно: при decode появляется unknown surface ` ⁇ `. Это существенное отличие от полного покрытия байтов в уроке tiktoken. SentencePiece также умеет byte fallback при соответствующем обучении модели; поведение нельзя определить только по названию библиотеки. BOS/EOS находятся в словаре, но автоматически к выводу данного примера не добавляются.

Модель и `reference.tsv` созданы официальным `sentencepiece==0.2.1`. Тест сверяет ID и decode Rust runtime с этими эталонами, включая случаи потери форматирования и неизвестного символа. Для пересоздания (не нужно для обычного запуска) установи Python-пакет этой версии в своё окружение и выполни:

```bash
python3 l252-57-tokenize-with-sentencepiece-unigram/data/train.py
```

Скрипт сохраняет `.model`, `.vocab` и эталоны рядом с корпусом. В protobuf trainer metadata записывает пути запуска, поэтому байты пересозданного файла могут отличаться при другом расположении проекта.

## Проверь понимание

1. Посчитай все три пути для изменённого словаря и объясни, почему самый длинный кусок проиграл.
2. Почему выбрать лучший первый кусок недостаточно для выбора лучшего полного пути?
3. Найди ID `▁` в `toy.vocab`. Почему это другой ID, чем в ручном словаре?
4. Почему декодирование пробелов и emoji здесь не повторяет исходную строку?

Готово, когда можешь объяснить `текст → нормализация → выбор кусков → ID`, отличить Unigram от BPE и назвать, что хранится в обученной модели помимо номеров.

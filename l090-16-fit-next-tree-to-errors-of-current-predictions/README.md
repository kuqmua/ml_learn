# Урок 090. Как следующее дерево исправляет ошибки текущего прогноза

Запуск из корня репозитория:

```bash
cargo run -p l090-16-fit-next-tree-to-errors-of-current-predicted_monthly_rents_thousand_rubles
```

Код находится в [src/main.rs](src/main.rs). Он выполняет все шаги последовательно и проверяет результаты через `assert!` и `assert_eq!`. При успешном запуске программа ничего не печатает; промежуточные вычисления разобраны ниже.

## 1. Что мы предсказываем

Представь, что нужно предсказывать месячную аренду квартиры по её площади. Это **выдуманные учебные данные**, а не реальные рыночные цены.

| Квартира | Площадь, м² — вход x | Аренда, тыс. рублей — ответ y |
|---|---:|---:|
| 1 | 20 | 20 |
| 2 | 30 | 24 |
| 3 | 40 | 28 |
| 4 | 50 | 32 |
| 5 | 60 | 48 |
| 6 | 70 | 52 |
| 7 | 80 | 56 |
| 8 | 90 | 60 |

В коде `apartment_areas_square_meters[apartment_index]` и `actual_monthly_rents_thousand_rubles[apartment_index]` относятся к одной квартире. `predicted_monthly_rents_thousand_rubles[apartment_index]` — текущий прогноз для неё. При обучении правильные ответы известны; при предсказании для новой квартиры будет известна только площадь.

## 2. Начинаем без деревьев

Пока не умеем учитывать площадь. Всем квартирам назначаем среднюю аренду:

```text
(20 + 24 + 28 + 32 + 48 + 52 + 56 + 60) / 8 = 40
```

Почему среднее? Среди постоянных прогнозов оно даёт наименьшую сумму квадратов ошибок на этих обучающих данных.

Для квартиры 20 м² прогноз 40 завышен: нужно его уменьшить. Для квартиры 90 м² прогноз 40 занижен: нужно увеличить.

## 3. Остаток говорит, в какую сторону исправлять прогноз

```text
остаток = правильный ответ − текущий прогноз
```

1. Квартира 20 м²: `20 − 40 = −20`. Нужно снизить прогноз на 20.
2. Квартира 90 м²: `60 − 40 = +20`. Нужно повысить прогноз на 20.
3. Все остатки: `[-20, -16, -12, -8, +8, +12, +16, +20]`.

Остаток — число со знаком. Квадрат ошибки всегда неотрицателен и не сообщает, повышать прогноз или понижать. Следующее дерево обучается предсказывать **остаток**, сохраняя площадь в качестве входного признака.

## 4. Где здесь дерево

Берём самое маленькое дерево: одна проверка и два листа. Такое дерево часто называют пнём (decision stump).

```text
                  площадь ≤ 55 м²?
                   /           \
                 да             нет
            левый лист       правый лист
            20–50 м²          60–90 м²
```

Лист — конечная группа объектов с одним общим предсказанием. Здесь предсказание дерева — поправка к аренде.

**Упрощение урока:** порог 55 задан заранее и одинаков для всех трёх деревьев. Мы обучаем значения листьев. В полноценном алгоритме обычно также ищут полезные признаки и пороги для каждого нового дерева. Код не реализует этот поиск.

Группу выбираем по площади, а не по положению квартиры в массиве. Если одинаково переставить пары «площадь, ответ», смысл вычислений сохранится.

## 5. Обучаем первое дерево

Нужно одно число для каждой группы. Для квадратичной ошибки лучшая постоянная поправка — средний остаток группы:

```text
Левый лист:  (−20 − 16 − 12 − 8) / 4 = −14
Правый лист: (+8 + 12 + 16 + 20) / 4 = +14
```

Первое дерево теперь умеет отвечать на любой вход:

1. Если площадь ≤ 55, вернуть `−14`.
2. Иначе вернуть `+14`.

Это не цены квартир. Это рекомендации: «снизь прежний прогноз на 14» или «повысь на 14».

## 6. Применяем часть поправки

В примере скорость обучения `fraction_of_tree_correction_to_apply = 0.5`:

```text
новый прогноз = старый прогноз + 0.5 × ответ дерева
```

1. Для левой группы: `40 + 0.5 × (−14) = 33`.
2. Для правой группы: `40 + 0.5 × (+14) = 47`.

Скорость обучения регулирует величину вклада нового дерева. Значение 0.5 выбрано, чтобы постепенные исправления было легко проследить; это не универсальная настройка.

Обрати внимание: квартира 50 м² имеет остаток −8, но получает ту же поправку −7, что и квартира 20 м² с остатком −20. Дерево видит только две группы и не может дать каждой квартире индивидуальную поправку.

## 7. Второе дерево получает уже другие учебные ответы

Теперь считаем остатки от прогнозов 33 и 47:

```text
Левая группа:  [20−33, 24−33, 28−33, 32−33] = [−13, −9, −5, −1]
Правая группа: [48−47, 52−47, 56−47, 60−47] = [+1, +5, +9, +13]
```

Средние остатки теперь `−7` и `+7`. Второе дерево даёт новые поправки:

```text
Левая группа:  33 + 0.5 × (−7) = 29.5
Правая группа: 47 + 0.5 × (+7) = 50.5
```

Третье дерево обучается на остатках от 29.5 и 50.5. Его листья равны −3.5 и +3.5; итоговые прогнозы — 27.75 и 52.25.

**Каждый раунд использует ошибку всей накопленной модели.** Если снова учить дерево на исходной аренде, получится другая процедура: мы перестанем явно обучать исправление оставшейся ошибки.

## 8. Как считаем качество

MSE — среднее квадратов остатков:

```text
MSE = ((ответ₁ − прогноз₁)² + ... + (ответ₈ − прогноз₈)²) / 8
```

В начале:

```text
(400 + 256 + 144 + 64 + 64 + 144 + 256 + 400) / 8 = 216
```

| Состояние | Прогноз для площади ≤ 55 | Прогноз для площади > 55 | MSE |
|---|---:|---:|---:|
| Без деревьев | 40 | 40 | 216 |
| После дерева 1 | 33 | 47 | 69 |
| После дерева 2 | 29.5 | 50.5 | 32.25 |
| После дерева 3 | 27.75 | 52.25 | 23.0625 |

Аренда и остатки измеряются в тысячах рублей, MSE — в квадрате этой единицы. В программе эти значения проверяются утверждениями `assert_eq!`.

Уменьшается средняя ошибка, но отдельный объект может стать хуже. Например, для квартиры 50 м² прогноз меняется с 33 на 29.5 при ответе 32: модуль остатка растёт с 1 до 2.5. Дерево оптимизирует общую ошибку группы.

Это качество **на обучающих данных**. Для проверки качества на новых квартирах понадобится отдельная выборка.

## 9. Почему ошибка не станет нулевой

Все деревья используют одну и ту же границу. Поэтому итоговая модель всегда имеет лишь два разных прогноза. Она не может одновременно предсказать 20, 24, 28 и 32 для четырёх объектов одной группы.

При продолжении этих обновлений прогнозы будут приближаться к средним ценам групп: 26 и 54. Даже тогда MSE равна 20, а не нулю. Чтобы различать объекты внутри групп, нужно разрешить другие разбиения или более сложные деревья.

## 10. Как предсказать аренду новой квартиры

Для новой квартиры 45 м² правильная аренда не нужна. Нужно сложить начальный прогноз и вклады обученных деревьев:

```text
40 + 0.5 × (−14) + 0.5 × (−7) + 0.5 × (−3.5) = 27.75
```

Для 75 м² будут правые листья: `40 + 7 + 3.5 + 1.75 = 52.25`.

Обучение использует правильные ответы для расчёта листьев. Готовая модель использует входную площадь, пороги и сохранённые значения листьев. Этот пример хранит текущие прогнозы, а формулу готового ансамбля показывает явно; сохранение модели здесь не реализовано.

## 11. Связь с градиентным бустингом

Для потери `L = 0.5 × (ответ − прогноз)²` производная по прогнозу равна `прогноз − ответ`. Её противоположность — как раз остаток `ответ − прогноз`. Поэтому обучение следующего дерева на остатках соответствует движению в направлении уменьшения квадратичной ошибки.

Для других функций потерь целевые значения следующего дерева могут отличаться от обычного остатка. Правило этого урока относится к регрессии с квадратичной ошибкой.

## 12. Проверь понимание

1. До запуска вычисли первый остаток, левый лист первого дерева и новый прогноз первой квартиры. Ответы: −20, −14, 33.
2. После первого дерева выпиши все восемь остатков. Проверь их по разделу 7.
3. Почему нельзя заменить `predicted_monthly_rents_thousand_rubles[apartment_index] += rent_correction_after_learning_rate` на `predicted_monthly_rents_thousand_rubles[apartment_index] = rent_correction_after_learning_rate`? Потому что `rent_correction_after_learning_rate` — лишь вклад нового дерева, а не полный прогноз аренды.
4. Почему нельзя использовать абсолютную величину остатка? Потеряется направление исправления.
5. Почему второе дерево возвращает ±7, а не ±14? Оно учится на новых остатках после первого обновления.
6. Что будет при скорости 1? Уже первый шаг даст прогнозы 26 и 54, MSE 20; следующие такие же разбиения дадут нулевые средние поправки.
7. Что будет при скорости 0? Прогнозы останутся 40, MSE — 216.
8. Поменяй местами две квартиры вместе с их ответами. Результаты для каждой площади и история MSE должны сохраниться.

При изменении параметров для опытов пересчитай ожидаемые значения в `assert_eq!`. Проверка строгого уменьшения MSE тоже рассчитана на исходный пример: при скорости 0 или после выхода на минимум ошибка не обязана уменьшаться. Срабатывание этих проверок при изменённом сценарии ожидаемо.

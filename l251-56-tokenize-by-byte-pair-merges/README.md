# 251 · От enumerate символов к BPE в tiktoken

Ты уже знаешь схему: собрать уникальные символы, через `enumerate` назначить ID, заменить символы числами. Например, отсортированный словарь для `banana`: `a=0, b=1, n=2`, текст → `[1,0,2,0,2,0]`. Один ID здесь всегда означает один символ.

В tiktoken идея словаря остаётся. Но записью может быть байт, часть слова, слово с пробелом или другой фрагмент. Новая задача — **выбрать границы кусков до получения ID**. Например, учебное `banana` можно представить одним ID, если такой кусок появился при обучении словаря. ID — адрес записи, а не значение слова и не embedding. Позже нейросеть использует ID для выбора строки таблицы эмбеддингов.

## Запуск

```bash
cargo run -p l251-56-tokenize-by-byte-pair-merges
cargo test -p l251-56-tokenize-by-byte-pair-merges
```

Код в `src/main.rs`. Первый запуск Cargo скачивает зависимости; словарь `cl100k_base` включён в `tiktoken-rs`, API-ключ и Python не нужны.

## 1. От символов к байтам

В UTF-8 `a` занимает один байт, `я` — два, emoji обычно несколько. `chars()` и `bytes()` дают разные последовательности. Учебный словарь сначала содержит все 256 байтов: ID байта равен его значению. Поэтому любой новый Unicode-текст уже представим без `<unk>`. В настоящем cl100k_base назначение ID байтам другое: наши номера нельзя переносить в него.

## 2. Как появляется словарь: обучение BPE

`train` начинает с отдельных байтов в трёх фрагментах `banana`, `banana`, `bandana`. Частые пары считаются по всему корпусу, но через границу фрагментов не проходят. В начале `an` встречается 6 раз, `na` — 5, `ba` — 3. Выбирается `an`, ему присваивается ID 256. Во всех фрагментах соседние `a,n` заменяются на один кусок, пары пересчитываются. Следующее объединение может соединить уже многобайтные куски.

Программа печатает выбранную пару, частоту и новый ID для каждого из четырёх шагов. При равных частотах используется лексикографический порядок байтов. Это условность нашего примера. При пересекающихся вхождениях замена идёт слева направо без перекрытий.

Обучение меняет словарь. Кодирование нового текста **не обучает его заново**: иначе те же числа стали бы обозначать другие куски и перестали подходить нейросети.

## 3. Как применять готовый словарь

`encode` начинает с байтов. Для каждой соседней пары ищет объединённый кусок в словаре. Из разрешённых выбирает кусок с минимальным рангом, объединяет одну пару, затем повторяет поиск. В учебном словаре ранг совпадает с ID: ранние объединения имеют приоритет. На этапе кодирования частоты входного текста уже не подсчитываются.

Это не правило «бери самый длинный префикс». Результат зависит от порядка разрешённых объединений. Флаг `trace` показывает каждый шаг для `banana`.

## 4. Настоящий tiktoken

Вторая половина main использует `tiktoken-rs` с настоящим `cl100k_base`: выводит ID, байты каждого токена и восстановленный текст. Сравни `banana` и ` banana`: пробел может входить в токен. На кириллице и emoji один токен иногда содержит лишь часть UTF-8 символа. Поэтому отдельный токен показываем через `from_utf8_lossy` только для просмотра; декодировать нужно соединённые байты всей последовательности. Знак `�` при просмотре части байтов не означает потерю исходного текста.

Полный путь tiktoken: обработка специальных токенов → regex-разбиение текста на фрагменты → byte-level BPE внутри фрагментов → ID. Учебный `encode` моделирует один такой фрагмент: здесь нет regex и специальных токенов, и он не воспроизводит cl100k_base. В реальном примере `encode_ordinary` считает даже похожие на специальные маркеры строки обычным текстом. Другой encoding означает другой словарь и другие ID.

## Проверь понимание

1. Почему `enumerate` уникальных символов нового запроса ломает совместимость с обученной сетью?
2. Увеличь число merges с 4 до 6: как изменятся длина словаря и число токенов `bandana`?
3. Замени корпус на тексты с кириллицей. Может ли новый токен содержать часть символа?
4. Почему нельзя декодировать каждый ID в отдельную Rust-строку и склеить строки?

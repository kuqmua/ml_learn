## 1. Почему инициализация меняет обучение

Большой случайный W2 даёт уверенные неправильные предсказания: начальная cross-entropy намного больше равномерного baseline `ln(27) ≈ 3.296`. В первой модели `W2 = randn * 0.01`, `b2 = 0`: сеть начинает с почти равномерных вероятностей.

Большой масштаб перед tanh загоняет нейроны в область около ±1. Производная `1-tanh(x)²` там мала, и обучение ранних слоёв замедляется. Для W1 используется `randn * (5/3)/sqrt(30)`: масштаб зависит от числа входов (fan-in), а gain 5/3 учитывает tanh. Notebook сохраняет историю промежуточных экспериментов в loss log; это результаты автора, а не обязательные числа для Rust.

Полезный опыт: сравни насыщение и начальную ошибку при gain 1, 5/3 и 5, затем увеличь W2 в 100 раз. Меняй одну настройку за запуск.

## 2. Первая модель: MLP с BatchNorm

```text
C[X]: (B,3,10) → flatten: (B,30)
→ Linear(30,200) без bias
→ BatchNorm(200) → tanh
→ Linear(200,27) + b2 → cross-entropy
```

Обучаются C, W1, gain, bias нормализации, W2 и b2: **12 097 параметров**. Смещение перед BatchNorm избыточно: вычитание среднего его устраняет. Смещение beta после нормализации остаётся обучаемым.

Для каждого нейрона отдельно по B=32 примерам:

```text
mean = sum(x) / B
variance = sum((x-mean)²) / (B-1)
std = sqrt(variance)
normalized = (x-mean) / std
output = gamma * normalized + beta
```

Здесь сохранена выборочная дисперсия исходного `torch.std`: делитель B−1. Поэтому выборочная дисперсия normalized равна 1, а средний квадрат равен (B−1)/B. Нельзя механически подставить формулу backward для делителя B.

На каждом шаге сохраняем EMA **стандартного отклонения** и среднего:

```text
running_mean = 0.999 * running_mean + 0.001 * batch_mean
running_std  = 0.999 * running_std  + 0.001 * batch_std
```

Running statistics — буферы, они не получают градиентов. На оценке используются эти буферы, независимо от состава группы. Первая версия notebook не добавляет epsilon; Rust ограничивает знаменатель снизу 1e-12 для вырожденного батча. Это защитное отличие от исходника.

200 000 обновлений SGD, 32 случайных примера с возвращением, lr=0.1 до шага 100 000, затем 0.01. Все градиенты вычисляются до обновления параметров. Для повторных букв в C используется scatter-add.

## 3. Как проходит градиент через BatchNorm

При upstream `g = dLoss/dOutput`, `z = normalized`, `s = sqrt(variance+eps)`:

```text
dBeta  = sum(g)
dGamma = sum(g*z)
dX = gamma/s * (g - sum(g)/B - z*sum(g*z)/(B-1))
```

Вычитание среднего связывает примеры батча: изменение одного входа меняет нормализацию остальных. Эта связь сохраняется в backward. Формула также учитывает epsilon через s и z. За пределами защитного clamp первой модели она проверяется центральными разностями.

Остальные производные: `dW = inputᵀ @ upstream`, `dInput = upstream @ Wᵀ`; tanh умножает градиент на `1-output²`; softmax с cross-entropy даёт `(probabilities-one_hot(target))/B`. Cross-entropy использует log-sum-exp, чтобы избежать переполнений.

## 5. Глубокая сеть и собственные слои

`Linear` и `BatchNorm` предоставляют forward/backward; выбор операции слоя и вычисления `Layer::Tanh` расположены прямо в проходах модели; `Model::parameters` собирает обучаемые параметры. Enum слоя позволяет хранить разные операции в одном списке без динамической библиотеки autograd.

```text
C: 27×10
Linear(30,100) → BN → tanh
4 × [Linear(100,100) → BN → tanh]
Linear(100,27) → BN(27)
```

Все Linear без смещений, начальные веса `randn/sqrt(fan_in)`. BN имеет gamma=1, beta=0, но у последнего BN gamma=0.1, чтобы уменьшить уверенность выходов. Всего **47 024 параметра**. Последний BN не сопровождается tanh.

Здесь нормализуем по `sqrt(variance+1e-5)`, EMA хранит **variance**, momentum=0.1. Среднее std и корень из среднего variance не равны: нельзя смешивать буферы двух частей. Как в самописном классе notebook, используется выборочная variance; это не точное воспроизведение стандартного `torch.nn.BatchNorm1d`, который иначе обрабатывает оценки дисперсии.

В notebook есть `if i >= 1000: break`: фактически выполняется **1001 обновление**, несмотря на max_steps=200000. Это отладочный запуск для изучения распределений. Число шагов в кортеже глубокой сети по умолчанию сохраняет его. При полном запуске lr падает на шаге 150 000.

## Проверка входных данных через типы

В областях использования внутри `main` объявлены типы с проверяемым созданием через `TryFrom` или методы словаря:

- `Vocabulary` хранит уникальные буквы в алфавитном порядке и точку под индексом 0. `new` строит словарь из текста, `len` возвращает его размер, `index_of` находит индекс символа, `character_index` проверяет числовой индекс, `character` возвращает символ с проверкой границ. `ContextCharacterIndices` хранит три `CharacterIndex`; целевой символ имеет тот же тип.
- `Names` — непустой список непустых имён из a–z; перемешивание сохраняет инвариант.
- `BatchColumns` — прямоугольный батч с положительной шириной и минимум двумя полными строками. Тип и его `TryFrom` определены внутри `BatchNorm::statistics`: входные значения проверяются перед расчётом, поэтому делитель выборочной дисперсии гарантированно положителен.
- `FiniteLoss` — конечное значение loss; NaN и бесконечности отклоняются до обновления параметров.

Строки ошибок `&'static str` проходят через `Result` и `?` от BatchNorm до `main`. Forward в режиме eval допускает один пример и использует сохранённые статистики. Входные `assert!` удалены; тестовые проверки результатов сохранены. Сохранены проверки передачи ошибок из сети и сохранности running statistics при неверном батче.
